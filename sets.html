Sets🔗

set 表示一个由不同元素组成的集合。以下数据类型都是 set：

  • hash set；

  • 使用 equal? 比较元素的 list；以及

  • 实现了 gen:set generic interface 的 struct 类型。

 (require racket/set) package: base
The bindings documented in this section are provided by the racket/set and racket libraries, but not racket/base.

1 Hash Sets🔗

hash set 是一种通过 equal?、equal-always?、 eqv? 或 eq? 比较元素，并通过 equal-hash-code、 equal-always-hash-code、eqv-hash-code 或 eq-hash-code 进行分区的 set。hash set 可以是不可变的或可变的；可变 hash set 可以强引用或弱引用 其元素。

与不可变 hash table 上的操作类似，“常数时间” hash set 操作实际上 对于大小为 N 的 set 需要 O(log N) 的时间。

hash set 可以用作 stream（参见 (part "streams")），因此也可以用作 单值 sequence（参见 (part "sequences")）。set 的元素用作 stream 或 sequence 的元素。如果在迭代期间向 hash set 添加或移除元素，则迭代步骤可能会因 exn:fail:contract 而失败，或者迭代可能会跳过或重复元素。另请参阅 in-set。

当两个 hash set 使用相同的元素比较过程（equal?、equal-always?、 eqv? 或 eq?）、都强引用或弱引用元素、具有相同的可变性、 并且具有等价的元素时，它们是 equal? 的。 不可变 hash set 支持有效的常数时间访问和更新，就像可变 hash set 一样；不可变操作的 常数因子通常更大，但不可变 hash set 的函数式特性在某些算法中可以发挥作用。

所有 hash set 实现 set->stream、set-empty?、 set-member?、set-count、subset?、 proper-subset?、set-map、set-for-each、 set-copy、set-copy-clear、set->list 和 set-first。不可变 hash set 还 实现 set-add、 set-remove、set-clear、set-union、 set-intersect、set-subtract 和 set-symmetric-difference。可变 hash set 还 实现 set-add!、set-remove!、set-clear!、 set-union!、set-intersect!、set-subtract! 和 set-symmetric-difference!。

对包含被变异元素的 set 的操作是不可预测的，这与当 key 被变异时 hash table 操作不可预测的方式大致相同。

2 Set Predicates and Contracts🔗

procedure

(generic-set? v) → boolean?

  v : any/c
如果 v 是 set，则返回 #t；否则返回 #f。

Examples:
> (generic-set? (list 1 2 3))

#t

> (generic-set? (set 1 2 3))

#t

> (generic-set? (mutable-seteq 1 2 3))

#t

> (generic-set? (vector 1 2 3))

#f

procedure

(set-implements? st sym ...) → boolean?

  st : generic-set?
  sym : symbol?
如果 st 实现了 gen:set 中由 sym 命名的所有方法， 则返回 #t；否则返回 #f。回退实现不影响结果；st 可能通过回退实现支持给定方法但仍产生 #f。

Examples:
> (set-implements? (list 1 2 3) 'set-add)

#t

> (set-implements? (list 1 2 3) 'set-add!)

#f

> (set-implements? (set 1 2 3) 'set-add)

#t

> (set-implements? (set 1 2 3) 'set-add!)

#t

> (set-implements? (mutable-seteq 1 2 3) 'set-add)

#t

> (set-implements? (mutable-seteq 1 2 3) 'set-add!)

#t

> (set-implements? (weak-seteqv 1 2 3) 'set-remove 'set-remove!)

#t

procedure

(set-implements/c sym ...) → flat-contract?

  sym : symbol?
识别支持 gen:set 中由 sym 命名的所有方法的 set。

procedure

(set/c elem/c    
  [#:cmp cmp    
  #:kind kind    
  #:lazy? lazy?    
  #:equal-key/c equal-key/c]) → contract?
  elem/c : chaperone-contract?
  cmp : (or/c 'dont-care 'equal 'equal-always 'eqv 'eq)
   = 'dont-care
  kind : (or/c 'dont-care 'immutable 'mutable 'weak 'mutable-or-weak)
   = 'immutable
  lazy? : any/c = 
(not (and (equal? kind 'immutable)
          (flat-contract? elem/c)))
  equal-key/c : contract? = any/c
构造一个识别元素匹配 elem/c 的 set 的 contract。

如果 kind 为 'immutable、'mutable 或 'weak，则生成的 contract 分别只接受不可变的、具有强引用 key 的可变、 或具有弱引用 key 的可变 hash set。如果 kind 为 'mutable-or-weak，则生成的 contract 接受任何可变 hash set， 不考虑 key 的持有强度。

如果 cmp 为 'equal、'equal-always、 'eqv 或 'eq，则生成的 contract 分别只接受使用 equal?、equal-always?、eqv? 或 eq? 比较元素的 hash set。

如果 cmp 为 'eqv 或 'eq，则 elem/c 必须是 flat contract。

如果 cmp 和 kind 都为 'dont-care，则生成的 contract 将接受任何类型的 set，而不仅仅是 hash set。

如果 lazy? 不为 #f，则 set 的元素不会被 contract 立即检查， 只有 set 本身被检查（根据 cmp 和 kind 参数）。如果 lazy? 为 #f，则元素会被 contract 立即检查。 当 set contract 接受通用 set 时（即 cmp 和 kind 都为 'dont-care），lazy? 参数被忽略；在那种情况下，被检查的值如果是 list?，则 contract 不是惰性的，否则 contract 是惰性的。

如果 kind 允许可变 set（即为 'dont-care、'mutable、 'weak 或 'mutable-or-weak）且 lazy? 为 #f，则元素会在立即检查时和从 set 中访问时都被检查。

equal-key/c contract 用于值被传递给内部使用的比较和哈希函数时。

结果 contract 在 elem/c 和 equal-key/c 都是 flat contract、 lazy? 为 #f、且 kind 为 'immutable 时 将是 flat contract。当 elem/c 是 chaperone contract 时，结果将是 chaperone contract。

Changed in version 8.3.0.9 of package base: 添加了对随机生成的支持。
Changed in version 8.5.0.3: 为 cmp 添加了 'equal-always 支持。

3 Generic Set Interface🔗

syntax

gen:set

一个 generic interface（参见 (part "struct-generics")），通过 struct 定义的 #:methods 选项为结构类型提供 set 方法实现。 此接口可用于实现 Set Methods 中记录的任何方法。

Examples:
> (struct binary-set [integer]
    #:transparent
    #:methods gen:set
    [(define (set-member? st i)
       (bitwise-bit-set? (binary-set-integer st) i))
     (define (set-add st i)
       (binary-set (bitwise-ior (binary-set-integer st)
                                (arithmetic-shift 1 i))))
     (define (set-remove st i)
       (binary-set (bitwise-and (binary-set-integer st)
                                (bitwise-not (arithmetic-shift 1 i)))))])
> (define bset (binary-set 5))
> bset

(binary-set 5)

> (generic-set? bset)

#t

> (set-member? bset 0)

#t

> (set-member? bset 1)

#f

> (set-member? bset 2)

#t

> (set-add bset 4)

(binary-set 21)

> (set-remove bset 2)

(binary-set 1)

3.1 Set Methods🔗

gen:set 的方法可以按其回退实现分为三类：

  1. 没有回退的方法，

  2. 回退依赖于其他非回退方法的方法，

  3. 以及回退可以依赖于回退或非回退方法的方法。

例如，实现以下方法将保证 gen:set 中的所有方法至少有一个回退方法：

  • set-member?

  • set-add

  • set-add!

  • set-remove

  • set-remove!

  • set-first

  • set-empty?

  • set-copy-clear

可能还有其他类似的方法子集可以保证每个方法至少有一个回退。

procedure

(set-member? st v) → boolean?

  st : generic-set?
  v : any/c
如果 v 在 st 中，返回 #t，否则返回 #f。 没有回退。

procedure

  st : generic-set?

产生一个包含 v 加上 st 所有元素的 set。对于 hash set 此操作在常数时间内运行。没有回退。

  st : generic-set?
  v : any/c
将元素 v 添加到 st。对于 hash set 此操作在常数时间 内运行。没有回退。

对于 hash set，另请参阅 hash table 的 caveats concerning concurrent modification， 该注意事项同样适用于 hash set。

procedure

(set-remove st v) → generic-set?

  st : generic-set?
  v : any/c
产生一个包含 st 中除 v 以外所有元素的 set。对于 hash set 此操作在常数时间内运行。没有回退。

procedure

(set-remove! st v) → void?

  st : generic-set?
  v : any/c
从 st 中移除元素 v。对于 hash set 此操作在常数时间 内运行。没有回退。

对于 hash set，另请参阅 hash table 的 caveats concerning concurrent modification， 该注意事项同样适用于 hash set。

procedure

(set-empty? st) → boolean?

  st : generic-set?
如果 st 没有成员，返回 #t；否则返回 #f。

支持任何 实现 set->stream 或 set-count 的 st。

procedure

(set-count st) → exact-nonnegative-integer?

  st : generic-set?
返回 st 中的元素数量。

支持任何 支持 set->stream 的 st。

procedure

(set-first st) → any/c

  st : (and/c generic-set? (not/c set-empty?))
产生 st 的一个未指定元素。对 st 的多次 set-first 使用产生相同的结果。

支持任何 实现 set->stream 的 st。

procedure

(set-rest st) → generic-set?

  st : (and/c generic-set? (not/c set-empty?))
产生一个包含 st 中除 (set-first st) 以外所有元素的 set。

支持任何 实现 set-remove 且 实现 set-first 或 set->stream 的 st。

procedure

(set->stream st) → stream?

  st : generic-set?
产生一个包含 st 元素的 stream。

支持任何 实现以下方法之一的 st：

  • set->list

  • in-set

  • set-empty?、set-first、set-rest

  • set-empty?、set-first、set-remove

  • set-count、set-first、set-rest

  • set-count、set-first、set-remove

procedure

(set-copy st) → generic-set?

  st : generic-set?
产生一个与 st 类型相同、元素相同的新可变 set。

支持任何 支持 set->stream 且 实现 set-copy-clear 和 set-add! 的 st。

procedure

(set-copy-clear st) → (and/c generic-set? set-empty?)

  st : generic-set?
产生一个与 st 类型、可变性和 key 强度相同的新空 set。

set-copy-clear 和 set-clear 的一个区别是，后者在概念上对 给定的 set 迭代执行 set-remove，因此它保留给定 set 上的任何 contract。 set-copy-clear 函数产生一个没有任何 contract 的新 set。

set-copy-clear 函数必须调用具体的 set 构造器，因此没有通用回退。

procedure

(set-clear st) → (and/c generic-set? set-empty?)

  st : generic-set?
产生一个与 st 类似但已移除所有元素的 set。

支持任何 实现 set-remove 且 支持 set->stream 的 st。

procedure

(set-clear! st) → void?

  st : generic-set?
从 st 中移除所有元素。

支持任何 实现 set-remove! 且 支持 set->stream 或 实现 set-first 和 set-count 或 set-empty? 的 st。

对于 hash set，另请参阅 hash table 的 caveats concerning concurrent modification， 该注意事项同样适用于 hash set。

procedure

(set-union st0 st ...) → generic-set?

  st0 : generic-set?
  st : generic-set?
产生一个与 st0 类型相同的 set，包含 st0 和所有 st 中的元素。

如果 st0 是 list，则每个 st 也必须是 list。此操作在 list 上 的运行时间与 st 的总大小乘以结果的大小成比例。

如果 st0 是 hash set，则每个 st 也必须是使用相同 比较函数（equal?、equal-always?、eqv? 或 eq?）的 hash set。hash set 的可变性和 key 强度可能不同。 此操作在 hash set 上的运行时间与除最大不可变 set 外所有 set 的总大小成比例。
