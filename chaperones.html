Impersonator 与 Chaperone🔗

impersonator 是对某个值的包装器，该包装器会重定向该值的某些操作。impersonator 仅适用于 procedure、具有可用 accessor 或 mutator 的 structure、structure type、hash table、vector、box、channel 和 prompt tag。 impersonator 与原始值之间是 equal? 的关系，但不是 eq? 的关系。

chaperone 是一种 impersonator，其对值的操作的细化仅限于副作用（特别是引发异常）或对操作提供或产生的值进行 chaperone。例如，vector chaperone 可以重定向 vector-ref使其在访问的 vector 槽包含字符串时引发异常，或者可以使 vector-ref 的结果成为访问的 vector 槽中值的 chaperoned 变体，但它不能重定向 vector-ref 以产生与 vector 槽中值任意不同的值。

相比之下，非 chaperone 的 impersonator 可以细化操作以将一个值替换为任意其他值。impersonator 不能应用于 immutable 值，也不能细化对 structure type 实例中 immutable 字段的访问，因为对操作的任意重定向等同于对 impersonated 值的 mutation。

请注意，以下每个操作都可以通过在操作的参数上的 impersonator 被重定向到任意 procedure——假设该操作对 impersonator 的创建者可用：

  • a structure-field accessor

  • a structure-field mutator

  • a structure type property accessor

  • application of a procedure

  • unbox

  • set-box!

  • vector-ref

  • vector-set!

  • hash-ref

  • hash-set

  • hash-set!

  • hash-remove

  • hash-remove!

  • channel-get

  • channel-put

  • call-with-continuation-prompt

  • abort-current-continuation

派生操作（如打印值）可以通过 impersonator 被重定向，因为它们底层使用了 accessor 函数。相比之下，equal?、equal-hash-code 和 equal-secondary-hash-code 操作可能会绕过 impersonator（但它们没有义务这样做）。

除了重定向作用于值的操作外，impersonator 还可以为 impersonated 值包含 impersonator property。impersonator property 类似于 structure type property，但它适用于 impersonator 而非 structure type 及其实例。

procedure

(impersonator? v) → boolean?

  v : any/c
如果 v 是由 impersonate-procedure 或 impersonate-struct 等 procedure 创建的 impersonator，则返回 #t，否则返回 #f。

程序和库通常应避免使用 impersonator?，将 impersonator 与非 impersonator 值同等对待。在极少数情况下，可能需要 impersonator? 来防止 impersonator 将操作重定向到任意 procedure。

impersonator? 的一个局限是它不识别通过实例化具有 prop:impersonator-of property 的 structure type 创建的 impersonator。这一局限反映了这些 impersonator 无法将 structure 访问和 mutation 操作重定向到任意 procedure。

procedure

(chaperone? v) → boolean?

  v : any/c
如果 v 是 chaperone，则返回 #t，否则返回 #f。

出于与应避免使用 impersonator? 相同的原因，程序和库通常应避免使用 chaperone?。chaperone? 返回真值意味着 impersonator? 也返回真值。

procedure

(impersonator-of? v1 v2) → boolean?

  v1 : any/c
  v2 : any/c
指示 v1 是否可以被认为在模除 impersonator 后与 v2 等价。

任何两个 eq? 的值也是 impersonator-of? 的。 对于不包含 impersonator 的值，如果 v1 和 v2 是 equal? 的，则认为它们互为对方的 impersonator。

如果 v1 或 v2 中至少有一个是 impersonator：

  • If v1 impersonates v1* then (impersonator-of? v1 v2) is #t if and only if (impersonator-of? v1* v2) is #t.

  • If v2 is a non-interposing impersonator that impersonates v2*, i.e., all of its interposition procedures are #f, then (impersonator-of? v1 v2) is #t if and only if (impersonator-of? v1 v2*) is #t.

  • When v2 is an impersonator constructed with at least one non-#f interposition procedure, but v1 is not an impersonator then (impersonator-of? v1 v2) is #f.

否则，如果 v1 和 v2 都不是 impersonator，但它们中任何一个包含 impersonator 作为子部分（例如 v1 是一个列表，其中一个元素是 impersonator），则 (impersonator-of? v1 v2) 通过递归比较 v1 和 v2（类似 equal?），在所有子部分都是 impersonator-of? 时返回真。

Examples:
> (impersonator-of? (impersonate-procedure add1 (λ (x) x))
                    add1)

#t

> (impersonator-of? (impersonate-procedure add1 (λ (x) x))
                    sub1)

#f

> (impersonator-of? (impersonate-procedure
                      (impersonate-procedure add1 (λ (x) x)) (λ (x) x))
                    add1)

#t

> (impersonator-of? (impersonate-procedure add1 (λ (x) x))
                    (impersonate-procedure add1 #f))

#t

> (impersonator-of? (impersonate-procedure add1 (λ (x) x))
                    (impersonate-procedure add1 (λ (x) x)))

#f

> (impersonator-of? (list 1 2)
                    (list 1 2))

#t

> (impersonator-of? (list (impersonate-procedure add1 (λ (x) x)) sub1)
                    (list add1 sub1))

#t

procedure

(chaperone-of? v1 v2) → boolean?

  v1 : any/c
  v2 : any/c
指示 v1 是否可以被认为在模除 chaperone 后与 v2 等价。

对于不包含 chaperone 或其他 impersonator 的值，如果 v1 和 v2 是 equal-always? 的，则可以认为它们互为对方的 chaperone。这要求它们是 equal? 的，但 v1 和 v2 中对应的 mutable vector、box、hash table、string、byte string、mutable pair 和 mutable structure 必须是 eq? 的。

否则，v2 中的 chaperone 和其他 impersonator 必须完整保留在 v1 中，类似于 impersonator-of? 要求保留 impersonator 的方式。此外，v1 不得包含任何非 chaperone 的 impersonator，其在 v2 中的对应值不是同一个 impersonator。请注意 chaperone-of? 蕴含 impersonator-of?，但反之不然。

procedure

(impersonator-ephemeron v) → ephemeron?

  v : any/c
生成一个 ephemeron，用于将 v 的可达性（在垃圾回收的意义上；参见 (part "gc-model")）与 v 是其 impersonator 的任何值的可达性关联起来。也就是说，只要结果 ephemeron 以及 v 所 impersonate 的任何值（包括自身）是可达的，值 v 就被认为是可达的。

在 ephemeron 的术语中，v 是 ephemeron 的 value，而 v 所 impersonate 的所有值都是 key。

procedure

(procedure-impersonator*? v) → boolean?

  v : any/c
对于由 impersonate-procedure* 或 chaperone-procedure* 产生的 procedure impersonator，或者是使用 impersonate-procedure* 或 chaperone-procedure* 创建的值的 impersonator/chaperone（可能通过传递性），返回 #t。

1 Impersonator 构造器🔗

procedure

(impersonate-procedure proc 
  wrapper-proc 
  prop 
  prop-val ... 
  ...) 
 → (and/c procedure? impersonator?)
  proc : procedure?
  wrapper-proc : (or/c procedure? #f)
  prop : impersonator-property?
  prop-val : any/c
返回一个 impersonator procedure，其 arity、名称和其他属性与 proc 相同。当 impersonator procedure 被应用时，参数首先传递给 wrapper-proc（当它不是 #f 时），然后 wrapper-proc 的结果传递给 proc。wrapper-proc 还可以提供一个处理 proc 结果的 procedure。

wrapper-proc 的 arity 必须包含 proc 的 arity。wrapper-proc 的允许关键字参数必须是 proc 允许关键字的超集。wrapper-proc 的必需关键字参数必须是 proc 必需关键字的子集。

对于不含关键字的应用，wrapper-proc 的结果必须至少与提供给它的参数数量相同。可以按以下模式提供额外的结果——在对应于所提供值的值之前：

  • An optional procedure, result-wrapper-proc, which will be applied to the results of proc; followed by

  • any number of repetitions of 'mark key val (i.e., three values), where the call proc is wrapped to install a continuation mark key and val.

如果提供了 result-wrapper-proc，它必须是一个 procedure，接受与 proc 产生的结果数量相同的参数；它必须返回相同数量的结果。如果没有提供 result-wrapper-proc，则 proc 在相对于 impersonator 调用的 tail position 中被调用。

对于包含关键字参数的应用，wrapper-proc 必须在其他值之前、但在 result-wrapper-proc 和 'mark key val 序列（如果有的话）之后，返回一个额外的值。该额外值必须是一个列表，其中包含提供给 impersonator 的关键字参数的替换值（即不计入未提供的可选参数）。参数必须按照所提供参数关键字的排序顺序排列。

如果 wrapper-proc 为 #f，则应用结果 impersonator 与应用 proc 相同。如果 wrapper-proc 为 #f 且未提供 prop，则返回 proc 且不进行 impersonate。

prop 和 prop-val 的配对（传递给 impersonate-procedure 的参数数量必须为偶数）添加 impersonator property 或覆盖 proc 的 impersonator-property 值。

如果任何 prop 是 impersonator-prop:application-mark，且关联的 prop-val 是一个 pair，则对 proc 的调用被包装在 with-continuation-mark 中，使用 (car prop-val) 作为 mark key，(cdr prop-val) 作为 mark value。此外，如果对 impersonated procedure 调用的直接 continuation 帧包含 (car prop-val) 的值——即如果 call-with-immediate-continuation-mark 会在调用的 continuation 中为 (car prop-val) 产生一个值——则该值也会在调用 wrapper-proc 期间作为 (car prop-val) 的直接 mark 值安装（这使得可以在 wrapper-proc 内检测到相对于包装 impersonator 的 impersonator 尾调用）。

Changed in version 6.3.0.5: Added support for 'mark key val results from wrapper-proc.

Examples:
> (define (add15 x) (+ x 15))
> (define add15+print
    (impersonate-procedure add15
                           (λ (x)
                             (printf "called with ~s\n" x)
                             (values (λ (res)
                                       (printf "returned ~s\n" res)
                                       res)
                                     x))))
> (add15 27)

42

> (add15+print 27)

called with 27

returned 42

42

> (define-values (imp-prop:p1 imp-prop:p1? imp-prop:p1-get)
    (make-impersonator-property 'imp-prop:p1))

    (make-impersonator-property 'imp-prop:p2))
> (define add15.2 (impersonate-procedure add15 #f imp-prop:p1 11))

> (define add15.3 (impersonate-procedure add15.2 #f imp-prop:p2 13))

> (imp-prop:p1? add15.3)

> (imp-prop:p1-get add15.3)

procedure

(impersonate-procedure* proc 
  wrapper-proc 
  prop 
  prop-val ... 
  ...) 
 → (and/c procedure? impersonator?)
  proc : procedure?
  wrapper-proc : (or/c procedure? #f)
  prop : impersonator-property?
  prop-val : any/c
类似于 impersonate-procedure，区别在于 wrapper-proc 在所有其他参数之前接收一个额外参数。该额外参数是最初被应用的 procedure orig-proc。

如果 impersonate-procedure* 的结果被直接应用，则 orig-proc 就是该结果。然而，如果该结果在被应用之前被进一步 impersonate，则 orig-proc 是进一步的 impersonator。

orig-proc 参数可能有用，例如使 wrapper-proc 能够提取被进一步 impersonator 覆盖的 impersonator property。

Added in version 6.1.1.5.

procedure

(impersonate-struct v    
  [struct-type]    
  orig-proc    
  redirect-proc ...    
  ...    
  prop    
  prop-val ...    
  ...) → any/c
  v : any/c
  struct-type : struct-type? = unspecified
  orig-proc : 
(or/c struct-accessor-procedure?
      struct-mutator-procedure?
      struct-type-property-accessor-procedure?)
  redirect-proc : (or/c procedure? #f)
  prop : impersonator-property?
  prop-val : any/c
返回 v 的 impersonator，它会重定向 impersonated 值上的某些操作。orig-proc 指定要重定向的操作，相应的 redirect-proc 提供重定向。可选的 struct-type 参数（如果提供）作为 v 表示的见证，v 必须是 struct-type 的实例。

redirect-proc 的协议取决于相应的 orig-proc，其中 self 表示 orig-proc 最初应用于的值：

  • A structure-field accessor: redirect-proc must accept two arguments, self and the value field-v that orig-proc produces for v; it must return a replacement for field-v. The corresponding field must not be immutable, and either the field’s structure type must be accessible via the current inspector or one of the other orig-procs must be a structure-field mutator for the same field.

  • A structure-field mutator: redirect-proc must accept two arguments, self and the value field-v supplied to the mutator; it must return a replacement for field-v to be propagated to orig-proc and v.

  • A property accessor: redirect-proc uses the same protocol as for a structure-field accessor. The accessor’s property must have been created with 'can-impersonate as the second argument to make-struct-type-property.

当 redirect-proc 为 #f 时，相应的 orig-proc 不受影响。为 redirect-proc 提供 #f 有助于让它的 orig-proc 作为 v 表示的"见证"并允许添加 prop。

prop 和 prop-val 的配对（如果提供了 struct-type，传递给 impersonate-struct 的参数数量必须为偶数，否则为奇数）添加 impersonator property 或覆盖 v 的 impersonator-property 值。

每个 orig-proc 必须指示一个不同的操作。 If no struct-type and no orig-procs are supplied, then no props must be supplied. If orig-procs are supplied only with #f redirect-procs and no props are supplied, then v is returned and is not impersonated.

如果任何 orig-proc 本身是一个 impersonator，则使用 orig-proc 所 impersonate 的 accessor 或 mutator 对于结果 impersonated structure 会被重定向，在 redirect-proc 之前（对于 accessor）或之后（对于 mutator）对 v 使用 orig-proc。

Changed in version 6.1.1.2: Changed first argument to an accessor or mutator redirect-proc from v to self.
Changed in version 6.1.1.8: Added optional struct-type argument.

procedure

(impersonate-vector vec 
  ref-proc 
  set-proc 
  prop 
  prop-val ... 
  ...) 
 → (and/c vector? impersonator?)
  vec : (and/c vector? (not/c immutable?))
  ref-proc : (or/c (vector? exact-nonnegative-integer? any/c . -> . any/c) #f)
  set-proc : (or/c (vector? exact-nonnegative-integer? any/c . -> . any/c) #f)
  prop : impersonator-property?
  prop-val : any/c
返回 vec 的 impersonator，它会重定向 vector-ref 和 vector-set! 操作。

ref-proc 和 set-proc 参数必须要么都是 procedure，要么都是 #f。如果它们都是 #f，则 impersonate-vector 不会拦截 vec，但仍允许附加 impersonator property。

如果 ref-proc 是 procedure，它必须接受 vec、传递给 vector-ref 的索引以及 vector-ref 在 vec 上为该索引产生的值；它必须产生该值的替换值，该替换值是 impersonator 上 vector-ref 的结果。

如果 set-proc 是 procedure，它必须接受 vec、传递给 vector-set! 的索引以及传递给 vector-set! 的值；它必须产生该值的替换值，该值用于原始 vec 上的 vector-set! 来安装该值。

prop 和 prop-val 的配对（传递给 impersonate-vector 的参数数量必须为奇数）添加 impersonator property 或覆盖 vec 的 impersonator-property 值。

Changed in version 6.9.0.2: Added non-interposing vector impersonators.

类似于 impersonate-vector，区别在于 ref-proc 和 set-proc 各接收 一个额外的向量作为参数，在其它参数之前。该额外参数是最初触发拦截的原始 impersonated vector。

额外的 vector 参数可能有用，例如使 ref-proc 或 set-proc 能够提取被进一步 impersonator 覆盖的 impersonator property。

Added in version 6.9.0.2.

procedure

(impersonate-box box    
  unbox-proc    
  set-proc    
  prop    
  prop-val ...    
  ...) → (and/c box? impersonator?)
  box : (and/c box? (not/c immutable?))
  unbox-proc : (box? any/c . -> . any/c)
  set-proc : (box? any/c . -> . any/c)
  prop : impersonator-property?
  prop-val : any/c
返回 box 的 impersonator，它会重定向 unbox 和 set-box! 操作。

unbox-proc 必须接受 box 以及 unbox 在 box 上产生的值；它必须产生一个替换值，该值是 impersonator 上 unbox 的结果。

prop 和 prop-val 的配对（传递给 impersonate-box 的参数数量必须为奇数）添加 impersonator property 或覆盖 box 的 impersonator-property 值。

procedure

(impersonate-hash hash    
  ref-proc    
  set-proc    
  remove-proc    
  key-proc    
  [clear-proc    
  equal-key-proc]    
  prop    
  prop-val ...    
  ...) → (and/c hash? impersonator?)
  hash : (and/c hash? (not/c immutable?))
  ref-proc : 
(hash? any/c . -> . (values
                     any/c
                     (hash? any/c any/c . -> . any/c)))
  set-proc : (hash? any/c any/c . -> . (values any/c any/c))
  remove-proc : (hash? any/c . -> . any/c)
  key-proc : (hash? any/c . -> . any/c)
  clear-proc : (or/c #f (hash? . -> . any)) = #f
  equal-key-proc : (or/c #f (hash? any/c . -> . any/c)) = #f
  prop : impersonator-property?
  prop-val : any/c
返回 hash 的 impersonator，它会重定向 hash-ref、hash-set! 或 hash-set（视情况适用）、hash-remove 或 hash-remove!（视情况适用）、hash-clear 或 hash-clear!（视情况适用且当 clear-proc 不是 #f 时）操作。当对 hash table 的 impersonator 使用 hash-set、hash-remove 或 hash-clear 时，结果是一个具有相同重定向 procedure 的 impersonator。 此外，像 hash-iterate-key 或 hash-map 这样从表中提取 key 的操作，使用 key-proc 来替换从表中提取的 key。像 hash-iterate-value 或 hash-values 这样的操作隐式使用 hash-ref，因此通过 ref-proc 重定向。hash-ref-key 操作同时使用 ref-proc 和 key-proc，前者查找请求的 key，后者提取它。

ref-proc 必须接受 hash 和传递给 hash-ref 的 key。它必须返回一个替换 key 以及一个 procedure。仅当返回的 key 通过 hash-ref 在 hash 中找到时，才会调用返回的 procedure，此时该 procedure 被调用时带有 hash、先前返回的 key 和找到的值。返回的 procedure 本身必须返回找到值的替换值。返回的 procedure 被 hash-ref-key 忽略。

set-proc 必须接受 hash、传递给 hash-set! 或 hash-set 的 key，以及传递给 hash-set! 或 hash-set 的值；它必须产生两个值：key 的替换值和值的替换值。返回的 key 和值用于原始 hash 上的 hash-set! 或 hash-set 来安装该值。

remove-proc 必须接受 hash 和传递给 hash-remove! 或 hash-remove 的 key；它必须产生该 key 的替换 key，该替换 key 用于原始 hash 上的 hash-remove! 或 hash-remove 来删除使用（已由 impersonator 替换的）key 的任何映射。

key-proc 必须接受 hash 和已从 hash 中提取的 key（通过 hash-ref-key、hash-iterate-key 或内部使用 hash-iterate-key 的其他操作）；它必须产生该 key 的替换 key，然后作为从表中提取的 key 报告。

如果 clear-proc 不是 #f，它必须接受 hash 作为参数，其结果被忽略。clear-proc 返回（而非引发异常或以其他方式转义）这一事实授予了从 hash 中移除所有 key 的能力。如果 clear-proc 是 #f，则 impersonator 上的 hash-clear 或 hash-clear! 使用 hash-iterate-key 和 hash-remove 或 hash-remove! 实现。

如果 equal-key-proc 不是 #f，它有效地拦截对 equal?、equal-hash-code 和 equal-secondary-hash-code 的调用，用于 hash 的 key。equal-key-proc 必须接受 hash 和一个 key（该 key 要么被 hash 映射，要么被传递给 hash-ref 等，后者可能已被相应的 ref-proc 等调整.）作为其参数。结果是一个值，根据需要传递给 equal?、equal-hash-code 和 equal-secondary-hash-code 以便对 key 进行哈希和比较。对于 hash-set! 或 hash-set，传递给 equal-key-proc 的 key 是存储在 hash table 中供将来查找的那个 key。

hash-iterate-value、hash-map 或 hash-for-each 函数结合使用 hash-iterate-key 和 hash-ref。如果 key-proc 产生的 key 没有通过 hash-ref 找到值，则 exn:fail:contract exception is raised。

对于 immutable hash table，当两个 impersonated hash table 的重定向 procedure 最初是通过同一个 impersonate-hash 或 chaperone-hash 调用附加到 hash table 的（并可能通过 hash-set、hash-remove 或 hash-clear 传播），只要第一个 hash table 的内容是第二个 hash table 的 impersonator-of?，则它们被视为"相同的值"（出于 impersonator-of? 的目的）。

prop:impersonator-of : struct-type-property?

一个 structure type property（参见 (part "structprops")），它提供一个 procedure 用于从表示 impersonator 的 structure 中提取 impersonated 值。该 property 用于 impersonator-of? 以及 equal?。

value

prop:authentic : struct-type-property?

一个 structure type property，它将 structure type 声明为 authentic。与该 property 关联的值被忽略；property 本身的存在使 structure type 成为 authentic。

authentic structure type 的实例不能通过 impersonate-struct 被 impersonate，也不能通过 chaperone-struct 被 chaperone。因此，authentic structure type 的实例只能在它是 flat contract 的情况下才能被赋予 contract（参见 struct/c）。

3 Impersonator Property🔗

procedure

(make-impersonator-property name)

 → 
impersonator-property?
(-> any/c boolean?)
(->* (impersonator?) (any/c) any)
  name : symbol?
创建一个新的 impersonator property 并返回三个值：

  • 一个 impersonator property descriptor，用于 impersonate-procedure、chaperone-procedure 和其他 impersonator 构造器；

  • 一个 impersonator property predicate procedure，它接受任意值，如果该值是一个具有该 property 值的 impersonator 则返回 #t，否则返回 #f；

  • 一个 impersonator property accessor procedure，它返回与 impersonator 关联的 property 值；如果传递给 accessor 的值不是 impersonator 或者不具有该 property 的值（即如果相应的 impersonator property predicate 返回 #f），则传递给 selector 的第二个可选参数决定其响应：如果未提供第二个参数则 exn:fail:contract exception is raised，如果第二个参数是 procedure 则不带参数尾调用它，否则返回第二个参数。
