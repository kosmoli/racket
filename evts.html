Events

Events🔗

A 可同步事件（或简称为 事件）与 sync 过程配合，用于协调线程之间的同步。某些类型的对象同时充当事件，包括 port 和 thread。其他类型的对象仅作为事件存在。Racket 的事件系统基于 Concurrent ML [Reppy99]。

在任何时刻，事件要么是 就绪可同步，要么不是；根据事件的种类以及它被其他线程使用的方式，事件可以在任何时候从非就绪切换到就绪（或反过来）。如果线程在事件就绪时对其进行同步，那么事件会产生一个特定的 同步结果。

同步事件可能会影响事件的状态。例如，当同步一个信号量时，其内部计数会递减，与 semaphore-wait 一样。然而对于大多数类型的事件（如 port），同步不会修改事件的状态。

用作 可同步事件 的 Racket 值包括 asynchronous channels, channels, custodian boxes, log receivers, place channels, ports, semaphores, subprocesses, TCP listeners, threads, and will executors. 库可以通过 prop:evt 定义新的可同步事件。

procedure

(evt? v) → boolean?

  v : any/c
Returns #t if v 是 可同步事件，否则返回 #f。

Examples:
> (evt? never-evt)

#t

> (evt? (make-channel))

#t

> (evt? 5)

#f

procedure

(sync evt ...) → any

  evt : evt?
阻塞直到至少有一个 可同步事件 evt 就绪为止。

当至少有一个 evt 就绪时，返回其 同步结果（通常是 evt 本身）。如果有多个 evt 就绪，则伪随机选择其中一个作为结果；控制此选择的随机数生成器由 current-evt-pseudo-random-generator 参数设置。

Examples:
> (define ch (make-channel))
> (thread (λ () (displayln (sync ch))))

#<thread>

> (channel-put ch 'hellooooo)

hellooooo

Changed in version 6.1.0.3: Allow 0 arguments instead of 1 or more.

procedure

(sync/timeout timeout evt ...) → any

  timeout : (or/c #f (and/c real? (not/c negative?)) (-> any))
  evt : evt?
如果 timeout 是 #f，则与 sync 相同。如果 如果 timeout 是实数，则当 timeout 秒过去后仍无成功同步时，结果为 #f。如果 timeout 是一个过程，则在轮询 evt 发现无就绪事件时，以尾位置调用该过程。

timeout 的零值等价于 (lambda () #f)。无论哪种情况，在返回 #f 或调用 timeout 之前，每个 evt 至少被检查一次。

另参见 alarm-evt，了解另一种超时机制。

Examples:
; times out before waking up
> (sync/timeout
   0.5
   (thread (λ () (sleep 1) (displayln "woke up!"))))

#f

> (sync/timeout
   (λ () (displayln "no ready events"))
   never-evt)

no ready events

Changed in version 6.1.0.3: Allow 1 argument instead of 2 or more.

procedure

(sync/enable-break evt ...) → any

  evt : evt?
类似于 sync，但在等待 evt 时启用 break（参见 (part "breakhandler")）。如果在调用 sync/enable-break 时 break 被禁用，那么要么所有 evt 都保持未选择状态，要么引发 exn:break 异常，但不会同时发生。

procedure

(sync/timeout/enable-break timeout evt ...) → any

  timeout : (or/c #f (and/c real? (not/c negative?)) (-> any))
  evt : evt?
类似于 sync/enable-break，但带有 sync/timeout 的超时参数。

创建一个组合多个 evt 的单一事件。将结果传递给 sync 与将每个 evt 传递给同一调用相同。

也就是说，当传递给 choice-evt 的一个或多个 evt 是 就绪可同步 时，choice-evt 返回的事件也是 就绪可同步 的。如果选择了该 choice 事件，则伪随机选择其中一个就绪的 evt，其 同步结果 即为所选 evt 的 同步结果。

Examples:
> (define ch1 (make-channel))
> (define ch2 (make-channel))
> (define either-channel (choice-evt ch1 ch2))
> (thread (λ () (displayln (sync either-channel))))

#<thread>

> (channel-put
   (if (> (random) 0.5) ch1 ch2)
   'tuturuu)

tuturuu

procedure

(wrap-evt evt wrap) → evt?

  evt : evt?
  wrap : (any/c ... . -> . any)
创建一个事件，当 evt 是 就绪可同步 时它也是 就绪可同步 的，但其 同步结果 由将 wrap 应用于 evt 的 同步结果 来确定。wrap 接受的参数数量必须与 evt 的同步结果值的数量匹配。

对 wrap 的调用通过 parameterize-break 在初始时禁用 break。

Examples:
> (define ch (make-channel))
> (define evt (wrap-evt ch (λ (v) (format "you've got mail: ~a" v))))
> (thread (λ () (displayln (sync evt))))

#<thread>

> (channel-put ch "Dear Alice ...")

you've got mail: Dear Alice ...

procedure

(handle-evt evt handle) → handle-evt?

  evt : evt?
  handle : (any/c ... . -> . any)
类似于 wrap-evt，但当它不被 wrap-evt、chaperone-evt 或另一个 handle-evt 包裹时，handle 会在同步请求的 尾位置 被调用——且不在显式禁用 break 的情况下调用。

Examples:
> (define msg-ch (make-channel))
> (define exit-ch (make-channel))
> (thread
   (λ ()
     (let loop ([val 0])
       (printf "val = ~a~n" val)
       (sync (handle-evt
              msg-ch
              (λ (val) (loop val)))
             (handle-evt
              exit-ch
              (λ (val) (displayln val)))))))

val = 0

#<thread>

> (channel-put msg-ch 5)

val = 5

> (channel-put msg-ch 7)

val = 7

> (channel-put exit-ch 'done)

done

procedure

(guard-evt maker) → evt?

  maker : (-> (or/c evt? any/c))
创建一个表现为事件但实际上是一个事件生成器的值。

guard-evt 返回的事件 guard 在 guard 与 sync 一起使用时生成一个事件（或者当它是与 sync 一起使用的 choice 事件的一部分时等），其中生成的事件是调用 maker 的结果。对于给定的 sync 调用，maker 最多被调用一次，但如果在此之前已选择了就绪事件，则 guard 甚至不会被考虑，maker 也不会被调用。

如果 maker 返回非事件值，则 maker 的结果被替换为一个 就绪可同步 的事件，其 同步结果 为 guard。

procedure

(nack-guard-evt maker) → evt?

  maker : (evt? . -> . (or/c evt? any/c))
类似于 guard-evt，但当 maker 被调用时，会传入一个 NACK（"否定确认"）事件。在开始调用 maker 之后，如果 maker 产生的事件最终没有被选为就绪事件，那么提供给 maker 的 NACK 事件将变为 就绪可同步，其值为 #<void>。

当事件因以下原因被放弃时，NACK 事件变为 就绪可同步：其他事件被选中、同步线程死亡、或控制从 sync 调用中逃逸（即使 nack-guard 的 maker 尚未返回值）。如果 maker 返回的事件被选中，则 NACK 事件永远不会变为 就绪可同步。

类似于 guard-evt，但当 maker 被调用时，会提供一个布尔值指示该事件将用于轮询（#t）还是用于阻塞同步（#f）。

如果向 maker 提供了 #t，且 break 被禁用，且轮询线程未被终止，且对结果事件的轮询产生了 同步结果，则该事件肯定会被选中用于其结果。

类似于 guard-evt，但 maker 仅在 evt 变为 就绪可同步 之后才被调用，并且 evt 的 同步结果 被传递给 maker。

尝试同步 evt 与尝试同步 replace-evt 的结果 guard 并发进行；尽管存在这种并发，但如果 maker 被调用，它会在同步 guard 的线程中被调用。evt 和另一个与 guard 同步的事件可以同时成功同步；同步的单选保证仅适用于 maker 的结果和与 guard 同步的其他事件。

如果 maker 返回非事件值，则 maker 的结果被替换为一个 就绪可同步 的事件，其 同步结果 为 guard。

Added in version 6.1.0.3.

value

always-evt : evt?

一个常量事件，始终 就绪可同步，其 同步结果 是它自身。

Example:
> (sync always-evt)

#<always-evt>

value

never-evt : evt?

一个常量事件，永远不会 就绪可同步。

procedure

(system-idle-evt) → evt?

返回一个当系统否则空闲时处于 就绪可同步 的事件：如果结果事件被 never-evt 替代，系统中没有任何线程可以运行。换句话说，所有线程必须已被挂起或仅在尚未超时的事件上阻塞。system-idle 事件的 同步结果 是 #<void>。system-idle-evt 过程的结果始终是同一事件。

Examples:
> (define th (thread (λ () (let loop () (loop)))))
> (sync/timeout 0.1 (system-idle-evt))

#f

> (kill-thread th)
> (sync (system-idle-evt))

procedure

(alarm-evt msecs [monotonic?]) → evt?

  msecs : real?
  monotonic? : any/c = #f
返回一个 可同步事件：当 (milliseconds) 返回的值小于 msecs 时不是 就绪可同步 的；当 (milliseconds) 返回的值大于 msecs 时是 就绪可同步 的。

Examples:
> (define alarm (alarm-evt (+ (current-inexact-milliseconds) 100)))
> (sync alarm)

#<alarm-evt>

Changed in version 8.3.0.9: Added the monotonic? argument.

procedure

(handle-evt? evt) → boolean?

  evt : evt?
如果 evt 是由 handle-evt 创建的，或者是通过对 handle-evt? 产生 #t 的另一个事件应用 choice-evt 创建的，则返回 #t。对于任何其他事件，handle-evt? 产生 #f。

Examples:
> (handle-evt? never-evt)

#f

> (handle-evt? (handle-evt always-evt values))

#t

value

prop:evt : struct-type-property?

一个 结构类型属性，用于标识其实例可作为 可同步事件 的结构类型。属性值可以是以下之一：

  • 事件 evt：此时，使用该结构作为事件等价于使用 evt。

  • 单参数过程 proc：此时，该结构类似于 guard-evt 生成的事件，但准 guard 过程 proc 接收该结构作为参数，而不是无参数；此外，proc 的非事件结果被替换为一个已经 就绪可同步 且其 同步结果 为该结构的事件。

  • 0（包含）到结构类型中非自动字段数量（不包含，不计算 supertype 字段）之间的精确非负整数：该整数标识结构中的一个字段，且该字段必须被指定为不可变。如果该字段包含一个对象或一个单参数的事件生成过程，则按上述方式使用该事件或过程。否则，该结构充当一个永不可用的事件。

对于使用外部库，prop:evt 的值也可以是 unsafe-poller 的结果，尽管该可能性被从 prop:evt 的安全契约中省略。

具有 prop:input-port 或 prop:output-port 属性的结构类型实例也因是 port 而充当 可同步事件。如果结构类型具有 prop:evt、prop:input-port 和 prop:output-port 中的多个，则 prop:evt 值（如有）优先决定实例作为事件的行为，且 prop:input-port 属性优先于 prop:output-port 用于同步。

Examples:
> (struct wt (base val)
    #:property prop:evt (struct-field-index base))
> (define sema (make-semaphore))
> (sync/timeout 0 (wt sema #f))

#f

> (semaphore-post sema)
> (sync/timeout 0 (wt sema #f))

#<semaphore>

> (semaphore-post sema)
> (sync/timeout 0 (wt (lambda (self) (wt-val self)) sema))

#<semaphore>

> (semaphore-post sema)
> (define my-wt (wt (lambda (self)
                      (wrap-evt
                       (wt-val self)
                       (lambda (x) self)))
                    sema))
> (sync/timeout 0 my-wt)

#<wt>

> (sync/timeout 0 my-wt)

#f
