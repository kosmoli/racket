Byte Strings🔗

(part ("(lib scribblings/guide/guide.scrbl)" "bytestrings")) in (part ("(lib scribblings/guide/guide.scrbl)" "top")) introduces byte strings.

byte string（字节字符串）是 byte 的定长数组。 byte（字节）是 0 到 255 之间（含两端）的精确整数。

A byte string 可以是 mutable（可变的）或 immutable（不可变的）。当不可变的 byte string 被传给像 bytes-set! 这样的过程时，会触发 exn:fail:contract exception is raised。默认 reader（参见 (part "parse-string")）生成的 byte string 常量是不可变的，并且在 read-syntax 模式下它们是 interned 的。 使用 immutable? 来检查 byte string 是否不可变。

当两个 byte string 长度相同且包含相同的 byte 序列时，它们是 equal? 的。

byte string 可以作为单值序列使用（参见 (part "sequences")）。byte string 中的 byte 作为序列的元素。 另见 in-bytes。

See (part "parse-string") for information on reading byte strings and (part "print-string") for information on printing byte strings.

另见：immutable?。

1 Byte String Constructors, Selectors, and Mutators🔗

procedure

(bytes? v) → boolean?

  v : any/c
如果 v 是 byte string 则返回 #t，否则返回 #f。

Examples:
> (bytes? #"Apple")

#t

> (bytes? "Apple")

#f

procedure

(make-bytes k [b]) → bytes?

  k : exact-nonnegative-integer?
  b : byte? = 0
返回一个新的长度为 k 的可变 byte string，其中每个 位置都用 byte b 初始化。

Example:
> (make-bytes 5 65)

#"AAAAA"

procedure

(bytes b ...) → bytes?

  b : byte?
返回一个新的可变 byte string，其长度为 提供的 b 的个数，各位置用给定的 b 初始化。

Example:
> (bytes 65 112 112 108 101)

#"Apple"

procedure

(bytes->immutable-bytes bstr) → (and/c bytes? immutable?)

  bstr : bytes?
返回一个与 bstr 内容相同的不可变 byte string，如果 bstr 本身已是不可变的，则直接返回 bstr 自身。

Examples:
> (bytes->immutable-bytes (bytes 65 65 65))

#"AAA"

> (define b (bytes->immutable-bytes (make-bytes 5 65)))
> (bytes->immutable-bytes b)

#"AAAAA"

> (eq? (bytes->immutable-bytes b) b)

#t

procedure

(byte? v) → boolean?

  v : any/c
如果 v 是 byte （即 0 到 255 之间含两端的精确整数）则返回 #t， 否则返回 #f。

Examples:
> (byte? 65)

#t

> (byte? 0)

#t

> (byte? 256)

#f

> (byte? -1)

#f

procedure

(bytes-length bstr) → exact-nonnegative-integer?

  bstr : bytes?
返回 bstr 的长度。

Example:
> (bytes-length #"Apple")

5

procedure

(bytes-ref bstr k) → byte?

  bstr : bytes?
  k : exact-nonnegative-integer?
返回 bstr 中位置 k 处的字节。 byte string 的第一个位置对应 0，因此位置 k 必须小于 byte string 的长度，否则将触发 exn:fail:contract exception is raised。

Example:
> (bytes-ref #"Apple" 0)

65

procedure

(bytes-set! bstr k b) → void?

  bstr : (and/c bytes? (not/c immutable?))
  k : exact-nonnegative-integer?
  b : byte?
将 bstr 中位置 k 处的字节更改为 b。byte string 的第一个 位置对应 0，因此位置 k 必须小于 byte string 的长度，否则将触发 exn:fail:contract exception is raised。

Examples:
> (define s (bytes 65 112 112 108 101))
> (bytes-set! s 4 121)
> s

#"Apply"

procedure

(subbytes bstr start [end]) → bytes?

  bstr : bytes?
  start : exact-nonnegative-integer?
  end : exact-nonnegative-integer? = (bytes-length str)
返回 一个新的长度为 (- end start) 的可变 byte string，包含 bstr 中从 start（含）到 end（不含）的相同字节。 start 和 end 参数必须小于或等于 bstr 的长度， 且 end 必须大于或等于 start，否则将触发 exn:fail:contract exception is raised。

Examples:
> (subbytes #"Apple" 1 3)

#"pp"

> (subbytes #"Apple" 1)

#"pple"

procedure

(bytes-copy bstr) → bytes?

  bstr : bytes?
返回 (subbytes str 0)。

procedure

(bytes-copy! dest    
  dest-start    
  src    
  [src-start    
  src-end]) → void?
  dest : (and/c bytes? (not/c immutable?))
  dest-start : exact-nonnegative-integer?
  src : bytes?
  src-start : exact-nonnegative-integer? = 0
  src-end : exact-nonnegative-integer? = (bytes-length src)
将 dest 中从位置 dest-start 开始的字节更改为 src 中从 src-start（含）到 src-end（不含）的字节。 byte string dest 和 src 可以是同一个 byte string， 在这种情况下目标区域可以与源区域重叠；复制后的目标字节匹配 复制前的源字节。如果 dest-start、src-start 或 src-end 中任何一个超出范围（考虑 byte string 的大小 以及源和目标区域），将触发 exn:fail:contract exception is raised。

Examples:
> (define s (bytes 65 112 112 108 101))
> (bytes-copy! s 4 #"y")
> (bytes-copy! s 0 s 3 4)
> s

#"lpply"

procedure

(bytes-fill! dest b) → void?

  dest : (and/c bytes? (not/c immutable?))
  b : byte?
将 dest 中每个位置都填充为 b。

Examples:
> (define s (bytes 65 112 112 108 101))
> (bytes-fill! s 113)
> s

#"qqqqq"

procedure

(bytes-append bstr ...) → bytes?

  bstr : bytes?
Returns 一个新的可变 byte string， 其长度为所有给定 bstr 长度之和，包含所有给定 bstr 的连接字节。如果没有提供 bstr，则结果为零长度的 byte string。

Example:
> (bytes-append #"Apple" #"Banana")

#"AppleBanana"

procedure

(bytes->list bstr) → (listof byte?)

  bstr : bytes?
返回一个与 bstr 内容对应的新的 byte 列表。即列表的长度为 (bytes-length bstr)，bstr 中的 byte 序列与 结果列表中的序列相同。

Example:
> (bytes->list #"Apple")

'(65 112 112 108 101)

procedure

(list->bytes lst) → bytes?

  lst : (listof byte?)
返回一个新的 可变 byte string，其内容为 lst 中的 byte 列表。 即 byte string 的长度为 (length lst)，lst 中的 byte 序列 与结果 byte string 中的序列相同。

Example:
> (list->bytes (list 65 112 112 108 101))

#"Apple"

procedure

(make-shared-bytes k [b]) → bytes?

  k : exact-nonnegative-integer?
  b : byte? = 0
返回一个新的长度为 k 的可变 byte string，其中每个 位置都用 byte b 初始化。 为了在 places 之间通信，新的 byte string 被分配在 shared memory space 中。

Example:
> (make-shared-bytes 5 65)

#"AAAAA"

procedure

(shared-bytes b ...) → bytes?

  b : byte?
返回一个新的可变 byte string， 其长度为提供的 b 的个数，各位置用给定的 b 初始化。 为了在 places 之间通信，新的 byte string 被分配在 shared memory space 中。

Example:
> (shared-bytes 65 112 112 108 101)

#"Apple"

2 Byte String Comparisons🔗

procedure

(bytes=? bstr1 bstr2 ...) → boolean?

  bstr1 : bytes?
  bstr2 : bytes?
如果 所有参数都是 eqv? 则返回 #t。

Examples:
> (bytes=? #"Apple" #"apple")

#f

> (bytes=? #"a" #"as" #"a")

#f

Changed in version 7.0.0.13: Allow one argument, in addition to allowing two or more.

procedure

(bytes<? bstr1 bstr2 ...) → boolean?

  bstr1 : bytes?
  bstr2 : bytes?
如果参数按字典序递增排列（其中单个 byte 按 < 排序）， 则返回 #t，否则返回 #f。

Examples:
> (bytes<? #"Apple" #"apple")

#t

> (bytes<? #"apple" #"Apple")

#f

> (bytes<? #"a" #"b" #"c")

#t

Changed in version 7.0.0.13: Allow one argument, in addition to allowing two or more.

procedure

(bytes>? bstr1 bstr2 ...) → boolean?

  bstr1 : bytes?
  bstr2 : bytes?
Like bytes<?, but checks whether the arguments are decreasing.

Examples:
> (bytes>? #"Apple" #"apple")

#f

> (bytes>? #"apple" #"Apple")

#t

> (bytes>? #"c" #"b" #"a")

3 Bytes to/from Characters, Decoding and Encoding🔗

procedure

(bytes->string/utf-8 bstr [err-char start end]) → string?

  bstr : bytes?
  err-char : (or/c #f char?) = #f
  start : exact-nonnegative-integer? = 0
  end : exact-nonnegative-integer? = (bytes-length bstr)
通过将 bstr 的 start 到 end 子串解码为 Unicode 码点的 UTF-8 编码来生成一个字符串。如果 err-char 不是 #f，则用于处理范围在 128 到 255 之间但不属于有效编码序列的字节。（此规则与从端口读取字符一致； 详见 (part "encodings")。）如果 err-char 是 #f， 且 bstr 的 start 到 end 子串整体上不是 有效的 UTF-8 编码，则触发 exn:fail:contract exception is raised。

Example:
> (bytes->string/utf-8 (bytes 195 167 195 176 195 182 194 163))

"çðö£"

4 Bytes to Bytes Encoding Conversion🔗

procedure

(bytes-open-converter from-name to-name)

 → (or/c bytes-converter? #f)
  from-name : string?
  to-name : string?
生成一个 byte converter（字节转换器），用于从 from-name 命名的编码转换到 to-name 命名的编码。如果请求的转换组合不可用， 则返回 #f 而非转换器。

某些编码组合始终可用：

  • (bytes-open-converter "UTF-8" "UTF-8") — 恒等转换， 但输入中的编码错误会导致解码失败。

  • (bytes-open-converter "UTF-8-permissive" "UTF-8") — the 恒等转换，但任何不属于有效编码序列的 输入字节都会被替换为 #\uFFFD 的 UTF-8 编码序列。 （这种对无效序列的处理与端口字节流到字符的解释一致； 参见 (part "ports")。）

  • (bytes-open-converter "" "UTF-8") — 从当前 locale 的 默认编码（参见 (part "encodings")）转换为 UTF-8。

  • (bytes-open-converter "UTF-8" "") — 从 UTF-8 转换为 当前 locale 的默认编码（参见 (part "encodings")）。

  • (bytes-open-converter "platform-UTF-8" "platform-UTF-16") — 在 Unix and Mac OS 上将 UTF-8 转换为 UTF-16，其中每个 UTF-16 码单元是由当前平台字节序排列的两个字节组成的序列。在 Windows 上， 转换等同于 (bytes-open-converter "WTF-8" "WTF-16") 以支持 未配对的代理码单元。

  • (bytes-open-converter "platform-UTF-8-permissive" "platform-UTF-16") — 类似于 (bytes-open-converter "platform-UTF-8" "platform-UTF-16")， 但不属于有效 UTF-8 编码序列（或在 Windows 上对未配对代理扩展无效）的 输入字节会被替换为 #\uFFFD。

  • (bytes-open-converter "platform-UTF-16" "platform-UTF-8") — 在 Unix and Mac OS 上将 UTF-16（按当前平台字节序排列的字节）转换为 UTF-8。 在 Windows 上，转换等同于 (bytes-open-converter "WTF-16" "WTF-8") 以支持未配对代理。在 Unix and Mac OS 上，假定代理是配对的：以 #xD800 位开始的一对字节构成代理对，使用该对和后续对的 #x03FF 位 （与 #xDC00 位的值无关）。在所有平台上，从输入 byte string 中 奇数偏移量处解码时性能可能较差。

  • (bytes-open-converter "WTF-8" "WTF-16") — 将 WTF-8 [Sapin18]（UTF-8 的超集）转换为 UTF-16 的超集 以支持未配对的代理码单元，其中每个 UTF-16 码单元是由当前平台字节序 排列的两个字节组成的序列。

  • (bytes-open-converter "WTF-8-permissive" "WTF-16") — 类似于 (bytes-open-converter "WTF-8" "WTF-16")， 但不属于有效 WTF-8 编码序列的输入字节会被替换为 #\uFFFD。

  • (bytes-open-converter "WTF-16" "WTF-8") — 将 WTF-16 [Sapin18]（UTF-16 的超集）转换为 WTF-8 （UTF-8 的超集）。输入可以包含未配对代理的 UTF-16 码单元， 相应的输出包含以 UTF-8 的自然扩展编码每个代理。

新打开的 byte converter 会注册到当前 custodian（参见 (part "custodians")）， 以便在 custodian 关闭时关闭该转换器。如果转换器是 Unix 上不涉及 "" 的保证组合之一，或者在 Windows 和 Mac OS 上是任何保证组合 （包括 ""），则不会注册到 custodian（也不需要关闭）。

在 Windows 的 Racket 软件发行版中，合适的 "iconv.dll" 包含在 "libmzschVERS.dll" 中。

可用的编码和组合因平台而异，取决于安装的 iconv 库； from-name 和 to-name 参数会传递给 iconv_open。 在 Windows 上，"iconv.dll" 或 "libiconv.dll" 必须与 "libmzschVERS.dll"（其中 VERS 是版本号）在同一目录下， 或者在用户的 PATH 中、系统目录中、或运行时当前可执行文件的目录中， 并且 DLL 必须提供 _errno 或链接到 "msvcrt.dll" 以获取 _errno； 否则，只有保证的组合可用。

procedure

(bytes-convert converter 
  src-bstr 
  [src-start-pos 
  src-end-pos 
  dest-bstr

  dest-end-pos])

(or/c bytes? exact-nonnegative-integer?)
exact-nonnegative-integer?

  converter : bytes-converter?
  src-bstr : bytes?
  src-start-pos : exact-nonnegative-integer? = 0

  dest-bstr : (or/c bytes? #f) = #f

转换 src-bstr 中从 src-start-pos 到 src-end-pos 的字节。

如果 dest-bstr 不是 #f，则将转换后的字节写入 dest-bstr 中从 dest-start-pos 到 dest-end-pos 的位置。 如果 dest-bstr 是 #f，则分配一个新的 byte string 来保存转换结果，如果 dest-end-pos 不是 #f， 则结果 byte string 的大小不超过 (- dest-end-pos dest-start-pos)。

bytes-convert 的结果为三个值：

  • result-bstr 或 dest-wrote-amt — 如果 dest-bstr 是 #f 或未提供，则为 byte string； 否则为写入 dest-bstr 的字节数。

  • src-read-amt — 从 src-bstr 成功转换的字节数。

  • 'complete、'continues、 'aborts 或 'error — 表示 转换如何终止：

    • 'complete：整个输入已处理，src-read-amt 等于 (- src-end-pos src-start-pos)。

    • 'continues：由于结果大小限制或 dest-bstr 中空间不足而停止转换；在这种情况下，如果处理 src-bstr 中下一个完整编码序列需要更多空间，可能返回少于 (- dest-end-pos dest-start-pos) 字节。

    • 'aborts：输入在编码序列中间停止，需要更多输入字节 才能继续。例如，如果对于 "UTF-8-permissive" 解码， 输入的最后一个字节是 195，则结果为 'aborts， 因为需要另一个字节来确定如何使用 195 字节。

    • 'error：src-bstr 中从 (+ src-start-pos src-read-amt) 开始的字节不构成合法的编码序列。 对于某些编码，此结果永远不会产生，因为所有字节序列都是有效的编码。 例如，由于 "UTF-8-permissive" 通过丢弃字符或生成 “?” 来处理 无效的 UTF-8 序列，因此每个字节序列实际上都是有效的。

应用转换器会在转换器中累积状态（即使 bytes-convert 的第三个结果是 'complete）。此状态可能影响后续的输入处理和输出生成， 但仅涉及流中用于切换模式的 “shift sequences” 的转换。要终止输入序列 并重置转换器，请使用 bytes-convert-end。

Examples:
> (define convert (bytes-open-converter "UTF-8" "UTF-16"))
> (bytes-convert convert (bytes 65 66 67 68))

#"\377\376A\0B\0C\0D\0"

4

'complete

> (bytes 195 167 195 176 195 182 194 163)

#"\303\247\303\260\303\266\302\243"

> (bytes-convert convert (bytes 195 167 195 176 195 182 194 163))

#"\347\0\360\0\366\0\243\0"

8

'complete

> (bytes-close-converter convert)

(bytes-convert-end converter 
  [dest-bstr 
  dest-start-pos 
  dest-end-pos])

(or/c 'complete 'continues)
  converter : bytes-converter?
  dest-bstr : (or/c bytes? #f) = #f
  dest-start-pos : exact-nonnegative-integer? = 0

类似于 bytes-convert，但此过程不是转换字节，而是生成转换的 结束序列（有时称为 “shift sequence”），如果有的话。很少有编码使用 shift sequence，因此对于大多数编码此函数将在无输出的情况下成功。 在任何情况下，成功输出一个（可能为空的）shift sequence 会将转换器 重置为初始状态。

bytes-convert-end 的结果为两个值：

  • result-bstr 或 dest-wrote-amt — 如果 dest-bstr 是 #f 或未提供，则为 byte string； 否则为写入 dest-bstr 的字节数。

  • 'complete 或 'continues — 表示转换是否完成。如果是 'complete，则已生成完整的结束序列。 如果是 'continues，则由于结果大小限制或 dest-bstr 中空间不足而无法完成转换，第一个结果为空 byte string 或 0。

procedure

(bytes-append* str ... strs) → bytes?

  str : bytes?
  strs : (listof bytes?)
类似于 bytes-append，但最后一个参数被用作 bytes-append 的参数列表，因此 (bytes-append* str ... strs) 等同于 (apply bytes-append str ... strs)。换言之，bytes-append 和 bytes-append* 之间的关系 类似于 list 和 list* 之间的关系。

Examples:
> (bytes-append* #"a" #"b" '(#"c" #"d"))

#"abcd"

> (bytes-append* (cdr (append* (map (lambda (x) (list #", " x))
                                     '(#"Alpha" #"Beta" #"Gamma")))))

#"Alpha, Beta, Gamma"
