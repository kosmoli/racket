Hash Tables🔗

(part ("(lib scribblings/guide/guide.scrbl)" "hash-tables")) in (part ("(lib scribblings/guide/guide.scrbl)" "top")) introduces hash tables.

hash table（或简称为 hash）将每个键映射到一个值。对于给定的 hash table，键通过 equal?、equal-always?、eqv? 或 eq? 进行等价比较，键的保留方式可以是强引用、弱引用（参见 (part "weakbox")）或类似 ephemerons 的方式。 hash table 也可以是可变的或不可变的。 不可变 hash table 支持等效的常数时间访问和更新，就像可变 hash table 一样；不可变操作的常数因子通常更大，但不可变 hash table 的函数式特性在某些算法中可以带来收益。使用 immutable? 来检查 hash table 是否不可变。

不可变 hash table 实际上提供 O(log N) 的访问和更新。由于 N 受地址空间限制，因此 log N 被限制在小于 30 或 62（取决于平台），log N 可以合理地被视为常数。

对于基于 equal? 的哈希，内建的 hash 函数作用于 strings、pairs、lists、vectors、 prefab 或透明的 structures、etc. 等时，其耗时与值的大小成正比。复合数据结构（如 list 或 vector）的哈希码取决于对容器中每个元素进行哈希，但这种递归哈希的深度是有限的（以避免循环数据的潜在问题）。对于非 list 的 pair，car 和 cdr 的哈希都被视为更深一层的哈希，但 list 的 cdr 被视为与该 list 具有相同的哈希深度。

hash table 可以作为双值 sequence 使用（参见 (part "sequences")）。hash table 的键和值作为序列的元素（即每个元素是一个键及其关联的值）。如果在迭代期间向 hash table 添加或移除映射，则迭代步骤可能会因 exn:fail:contract 而失败，或者迭代可能会跳过或重复键和值。另请参见 in-hash、in-hash-keys、in-hash-values 和 in-hash-pairs。

两个 hash table 除非具有相同的可变性、使用相同的键比较过程（equal?、equal-always?、eqv? 或 eq?）、且都以强引用、弱引用或类似 ephemerons 的方式持有键，否则它们不可能 equal?。 空的不可变 hash table 在 equal? 时也是 eq? 的。

Changed in version 7.2.0.9: 使空的不可变 hash table 在 equal? 时也是 eq? 的。

关于并发修改的注意事项： 可变 hash table 可以被多个线程通过 hash-ref、hash-set! 和 hash-remove! 并发操作，并且这些操作在需要时受到表特定信号量的保护。然而，有一些注意事项：

  • 如果线程在对使用 equal?、equal-always? 或 eqv? 键比较的 hash table 执行 hash-ref、 hash-ref-key、hash-set!、hash-remove!、 hash-ref!、hash-update! 或 hash-clear! 时被终止，则当前和将来对该 hash table 的所有操作可能会无限期阻塞。

  • hash-map、hash-for-each 和 hash-clear! 过程不会使用表的信号量来保护整个遍历过程（如果需要遍历的话，如 hash-clear! 的情况）。 一个线程对 hash table 的更改可能影响另一个线程在遍历同一 hash table 过程中看到的键和值。

  • hash-update! 和 hash-ref! 函数 分别对 hash-ref 和 hash-set! 部分独立使用表的信号量，这意味着整个更新操作不是"原子的"。

  • 将可变 hash table 自身作为键添加到自身是有问题的，因为键正在被修改（参见下面的注意事项），而且这也是一种对 hash table 的并发使用：计算 hash table 的哈希码可能需要等待表的信号量，但信号量已被修改 hash table 的操作持有，因此 hash table 的添加操作可能会无限期阻塞。

关于可变键的注意事项： 如果基于 equal? 的 hash table 中的键被修改（例如，使用 string-set! 修改键字符串），则 hash table 的插入和查找操作将变得不可预测。

字面量或打印的 hash table 以 #hash、 #hashalw、#hasheqv 或 #hasheq 开头。See (part "parse-hashtable") for information on reading hash tables and (part "print-hashtable") for information on printing hash tables.

(hash-ref hash key [failure-result]) → any

  hash : hash?
  key : any/c
  failure-result : failure-result/c
   = 
(lambda ()
  (raise (make-exn:fail:contract ....)))
返回 hash 中 key 对应的值。如果未找到 key 的值，则 failure-result 决定结果：

  • 如果 failure-result 是一个过程，则通过尾调用 不带参数调用它来产生结果。

  • 否则，failure-result 作为结果返回。

procedure

(hash-ref-key hash key [failure-result]) → any

  hash : hash?
  key : any/c
  failure-result : failure-result/c
   = 
(lambda ()
  (raise (make-exn:fail:contract ....)))
返回 hash 持有的与 key 根据 hash 的键比较函数等价的键。如果未找到键， 则按 hash-ref 中的方式使用 failure-result 来确定结果。

如果 hash 不是 impersonator，则返回的键 （假设找到的话）将与 hash 实际持有的键是 eq? 等价的：

Examples:
> (define original-key "hello")
> (define key-copy (string-copy original-key))
> (equal? original-key key-copy)

#t

> (eq? original-key key-copy)

#f

> (define table (make-hash))
> (hash-set! table original-key 'value)
> (eq? (hash-ref-key table "hello") original-key)

#t

> (eq? (hash-ref-key table "hello") key-copy)

#f

如果可变 hash 使用不是 eq? 等价但根据 hash 的键比较过程等价的键多次更新，hash 保留第一个键：

Examples:
> (define original-key "hello")
> (define key-copy (string-copy original-key))
> (define table (make-hash))
> (hash-set! table original-key 'one)
> (hash-set! table key-copy 'two)
> (eq? (hash-ref-key table "hello") original-key)

#t

> (eq? (hash-ref-key table "hello") key-copy)

#f

相反，不可变 hash 保留最近用于更新它的键：

Examples:
> (define original-key "hello")
> (define key-copy (string-copy original-key))
> (define table0 (hash))
> (define table1 (hash-set table0 original-key 'one))
> (define table2 (hash-set table1 key-copy 'two))
> (eq? (hash-ref-key table2 "hello") original-key)

#f

> (eq? (hash-ref-key table2 "hello") key-copy)

#t

如果 hash 是 impersonator，则返回的键 将按 impersonate-hash 文档中描述的方式确定。

另请参见上面的 caveats concerning concurrent modification 和 caveat concerning mutable keys。

Added in version 7.4.0.3.

  updater    
  [failure-result]) → void?

procedure

(hash-map hash proc [try-order?]) → (listof any/c)

  hash : hash?
  proc : (any/c any/c . -> . any/c)
  try-order? : any/c = #f
以未指定的顺序将过程 proc 应用于 hash 中的每个元素，将结果累积到列表中。过程 proc 每次被调用时 接收一个键和它的值，过程的各个结果按顺序出现在结果列表中。

如果在 hash-map 或 hash-for-each 遍历进行期间，hash table 被扩展了新键（通过 proc 或由另一个线程），遍历中可能会丢弃或重复任意键值对。键映射可以 被删除或重新映射（由任何线程）而不会产生不良影响；如果键已经被看到， 更改不会影响遍历，否则遍历会跳过已删除的键或使用重新映射的键的新值。

另请参见上面的 caveats concerning concurrent modification。

如果 try-order? 为真，则传递给 proc 的键和值的顺序在某些情况下 会被规范化——包括当每个键是以下类型之一时，按以下顺序（前面的项目排在后面的项目之前）：

  • booleans 按 #f 排在 #t 之前排序；

  • characters 按 char<? 排序；

  • real numbers 按 < 排序；

  • symbols 按 uninterned symbols 排在 unreadable symbols 之前，再排在 interned symbols 之前， 然后按 symbol<? 排序；

  • keywords 按 keyword<? 排序；

  • strings 按 string<? 排序；

  • byte strings 按 bytes<? 排序；

  • null；

  • #<void>；以及

  • eof。

Changed in version 6.3: 添加了 try-order? 参数。
Changed in version 7.1.0.7: 添加了对 try-order? 的保证。

procedure

(hash-union h0 
  h ... 
  [#:combine combine 
  #:combine/key combine/key]) 
 → (and/c hash? immutable?)
  h0 : (and/c hash? immutable?)
  h : hash?
  combine : (-> any/c any/c any/c)
   = (lambda _ (error 'hash-union ....))
  combine/key : (-> any/c any/c any/c any/c)
   = (lambda (k a b) (combine a b))
通过函数式更新计算 h0 与每个 hash table h 的并集， 依次将每个 h 的每个元素添加到 h0。对于每个 键 k 和值 v，如果从 k 到某个值 v0 的映射已经存在，则将其替换为从 k 到 (combine/key k v0 v) 的映射。

Examples:
> (hash-union (make-immutable-hash '([1 . one]))
              (make-immutable-hash '([2 . two]))
              (make-immutable-hash '([3 . three])))

'#hash((1 . one) (2 . two) (3 . three))

> (hash-union (make-immutable-hash '([1    one uno]  [2    two dos]))
              (make-immutable-hash '([1    eins un]  [2    zwei deux]))
              #:combine/key (lambda (k v1 v2) (append v1 v2)))

'#hash((1 . (one uno eins un)) (2 . (two dos zwei deux)))

procedure

(hash-intersect h0 
  h ... 
  [#:combine combine 
  #:combine/key combine/key]) 
 → (and/c hash? immutable?)
  h0 : (and/c hash? immutable?)
  h : hash?
  combine : (-> any/c any/c any/c)
   = (lambda _ (error 'hash-intersect ...))
  combine/key : (-> any/c any/c any/c any/c)
   = (lambda (k a b) (combine a b))
构造 h0 与每个 hash table h 的交集 hash table。 在结果 hash table 中，键 k 映射到 k 在每个 hash table 中映射的值的组合。最终值 通过对每个 hash table 中出现的值进行逐步组合来计算， 方法是应用 (combine/key k v vi) 或 (combine v vi)，其中 vi 是 k 在第 i 个 hash table h 中映射的值，v 是前面步骤的累积值。 第一个参数的比较谓词（eq?、 eqv?、equal-always?、equal?）决定结果的比较谓词。

Examples:
> (hash-intersect (make-immutable-hash '((a . 1) (b . 2) (c . 3)))
                  (make-immutable-hash '((a . 4) (b . 5)))
                  #:combine +)

'#hash((a . 5) (b . 7))

> (hash-intersect (make-immutable-hash '((a . 1) (b . 2) (c . 3)))
                  (make-immutable-hash '((a . 4) (b . 5)))
                  #:combine/key
                  (lambda (k v1 v2) (if (eq? k 'a) (+ v1 v2) (- v1 v2))))

'#hash((a . 5) (b . -3))
