正则表达式🔗

(part ("(lib scribblings/guide/guide.scrbl)" "regexp")) in (part ("(lib scribblings/guide/guide.scrbl)" "top")) introduces regular expressions.

正则表达式以字符串或字节字符串的形式指定， 使用的模式语言与 Unix 工具 egrep 或 Perl 相同。 字符串指定的模式产生字符 regexp 匹配器，字节字符串模式产生 字节 regexp 匹配器。如果字符 regexp 用于字节字符串或输入端口， 它匹配匹配字符流的 UTF-8 编码（参见 (part "encodings")）； 如果字节 regexp 用于字符串，它匹配该字符串 UTF-8 编码中的字节。

以字符串或字节字符串形式表示的正则表达式可以编译为 regexp 值，与字符串或字节字符串形式相比， regexp-match 等函数可以更高效地使用它。 regexp 和 byte-regexp 过程分别将字符串 或字节字符串转换为 regexp 值，使用与 egrep 最兼容的 正则表达式语法。pregexp 和 byte-pregexp 过程 使用与 Perl 更兼容的稍有不同的正则表达式语法生成 regexp 值。

两个 regexp 值如果具有相同的源、使用相同的模式语言、 且都是字符 regexp 或都是字节 regexp，则是 equal? 的。

字面量或打印的 regexp 值以 #rx 或 #px 开头。See (part "parse-regexp") for information on reading 正则表达式 and (part "print-regexp") for information on printing 正则表达式. 默认 reader 生成的 Regexp 值在 read-syntax 模式下 是 interned 的。

在 Racket 的 BC 变体上， regexp 值的内部大小限制为 32 KB；此限制大致对应 于包含 32,000 个文字字符或 5,000 个运算符的源字符串。

2 附加语法约束🔗

除了匹配语法之外，正则表达式还必须满足两个语法限制：

  • 在除 ‹atom›? 之外的 ‹repeat› 中， ‹atom› 不得匹配空序列。

  • 在 (?<=‹regexp›) 或 (?<!‹regexp›) 中， ‹regexp› 只能匹配有界序列。

这些约束通过以下类型系统在语法上进行检查。类型 [n, m] 对应于匹配 n 到 m 个 字符的表达式。在 (‹regexp›) 的 规则中，‹n› 表示使得左括号是用于收集匹配报告的第 ‹n› 个左括号的数字。对于反向引用模式 \‹n›，会推断非空性，以便反向引用可以 用于重复模式；在反向引用之间存在相互依赖的情况下，推断会选择 最大化非空性的不动点。对反向引用不推断有限性（即假设反向引用 匹配任意大的序列）。没有语法约束禁止在反向引用所引用的组内 使用反向引用，尽管这种自引用可能会创建没有可能匹配的模式 （如 (.\1) 的情况，尽管 (^.|\1){2} 匹配以相同两个字符开头的输入）。

4 正则表达式匹配🔗

procedure

(regexp-match pattern 
  input 
  [start-pos 
  end-pos 
  output-port 
  input-prefix]) 
 → 
(if (and (or (string? pattern) (regexp? pattern))
         (or (string? input) (path? input)))
    (or/c #f (cons/c string? (listof (or/c string? #f))))
    (or/c #f (cons/c bytes?  (listof (or/c bytes?  #f)))))
  pattern : (or/c regexp? byte-regexp? string? bytes?)
  input : (or/c string? bytes? path? input-port?)
  start-pos : exact-nonnegative-integer? = 0
  end-pos : (or/c exact-nonnegative-integer? #f) = #f
  output-port : (or/c output-port? #f) = #f
  input-prefix : bytes? = #""
尝试将 pattern（字符串、字节字符串、regexp 值 或 byte-regexp 值）与 input 的一部分进行一次 匹配。匹配器找到 input 中匹配且最接近输入开头 （在 start-pos 之后）的部分。

如果 input 是一个 path，且 pattern 是 字节字符串或基于字节的 regexp，则使用 path->bytes 将其转换为字节字符串。否则，使用 path->string 将 input 转换为字符串。

可选的 start-pos 和 end-pos 参数选择 input 的一部分进行匹配；默认为整个字符串或直到 文件结尾的流。当 input 是字符串时， start-pos 是字符位置；当 input 是字节 字符串时，start-pos 是字节位置；当 input 是输入端口时，start-pos 是开始匹配 前要跳过的字节数。end-pos 参数可以是 #f，对应字符串的末尾或流中的文件结尾；否则，它像 start-pos 一样是字符或字节位置。如果 input 是输入端口，并且在跳过 start-pos 字节之前到达文件结尾，则匹配失败。

在 pattern 中，字符串开头的 ^ 指的是 input 在 start-pos 之后的第一个位置， 假设 input-prefix 是 #""。输入末尾的 $ 指的是第 end-pos 个位置或（在输入 端口的情况下）文件结尾，以先到者为准。

input-prefix 指定有效地在 input 之前的 字节，用于 ^ 和其他 look-behind 匹配。例如， #"" 前缀意味着 ^ 在流的开头匹配， 而 #"\n" input-prefix 意味着行首 ^ 可以匹配输入的开头，而文件开头 ^ 则不能。

如果匹配失败，返回 #f。如果匹配成功，返回一个 包含字符串或字节字符串（可能还有 #f）的列表。 仅当 input 是字符串且 pattern 不是字节 regexp 时，列表才包含字符串。否则，列表包含字节字符串 （如果 input 是字符串，则为 input 的 UTF-8 编码的子串）。

结果列表中的第一个（字节）字符串是 input 中匹配 pattern 的部分。如果 input 的两个部分 可以匹配 pattern，则找到最早开始的那个匹配。

如果 pattern 包含带括号的子表达式（但左括号后跟 ?时除外），则列表中返回额外的（字节）字符串。 子表达式的匹配按 pattern 中左括号的顺序提供。 当子表达式出现在 | “或”模式的分支中、 * “零次或多次”模式中，或者其他整体模式 可以成功而子表达式不匹配的地方时，如果子表达式没有贡献 最终匹配，则返回 #f。当单个子表达式出现在 * “零次或多次”模式或其他多次匹配位置中时， 列表中返回与该子表达式关联的最右匹配。

如果提供了可选的 output-port 作为输出端口，则 input 中从开头（不是 start-pos）到匹配 之前的部分会被写入端口。如果没有找到匹配，则将 input 到 end-pos 的全部内容写入端口。 当 input 是输入端口时，此功能最有用。

当匹配输入端口时，匹配失败会读取最多 end-pos 字节 （或文件结尾），即使 pattern 以字符串开头 ^ 开始；另请参见 regexp-try-match。 成功时，最终会从端口读取直到并包括匹配的所有字节，但匹配 过程是先 peek 端口的字节（使用 peek-bytes-avail!）， 然后在匹配结果确定后（重新）读取匹配的字节以丢弃它们。 不匹配的字节可能在匹配确定之前被读取和丢弃。匹配器仅在 必要时以阻塞模式 peek 以确定匹配，但如果立即可用（即无需 阻塞），它可能 peek 额外的字节来填充内部缓冲区。 pattern 中的贪婪重复运算符，如 * 或 +，往往会强制读取端口的全部内容（直到 end-pos）以确定匹配。

如果输入端口同时被另一个线程读取，或者端口是具有不一致的 读取和 peek 过程的自定义端口（参见 (part "customport")）， 则 peeked 并用于匹配的字节可能与匹配完成后读取并丢弃的 字节不同；匹配器仅检查 peek 的字节。为避免这种交错， 使用 regexp-match-peek（带 progress 参数）后跟 port-commit-peeked。

Examples:
> (regexp-match #rx"x." "12x4x6")

'("x4")

> (regexp-match #rx"y." "12x4x6")

#f

> (regexp-match #rx"x." "12x4x6" 3)

'("x6")

> (regexp-match #rx"x." "12x4x6" 3 4)

#f

> (regexp-match #rx#"x." "12x4x6")

'(#"x4")

> (regexp-match #rx"x." "12x4x6" 0 #f (current-output-port))

12

'("x4")

> (regexp-match #rx"(-[0-9]*)+" "a-12--345b")

'("-12--345" "-345")

procedure

(regexp-match* pattern 
  input 
  [start-pos 
  end-pos 
  input-prefix 
  #:match-select match-select 
  #:gap-select? gap-select]) 
 →

         (or (string? input) (path? input)))
    (listof (or/c string? (listof (or/c #f string?))))
    (listof (or/c bytes? (listof (or/c #f bytes?)))))
  pattern : (or/c regexp? byte-regexp? string? bytes?)
  input : (or/c string? bytes? path? input-port?)
  start-pos : exact-nonnegative-integer? = 0
  end-pos : (or/c exact-nonnegative-integer? #f) = #f
  input-prefix : bytes? = #""
  match-select : 
(or/c (list? . -> . (or/c any/c list?))
      #f)
 = car
  gap-select : any/c = #f
类似于 regexp-match，但结果是一个字符串或字节 字符串的列表，对应 input 中 pattern 的 一系列匹配。

pattern 按顺序用于查找匹配，每次匹配尝试从上次 匹配的末尾开始，^ 仅对第一次匹配允许匹配输入的 开头（如果 input-prefix 是 #""）。 空匹配像其他匹配一样处理，返回零长度的字符串或字节序列 （它们在使其成为 regexp-split 的补充方面更有用）， 但 pattern 被限制不能在空匹配之后立即匹配空序列。

如果 input（在 start-pos 到 end-pos 范围内）不包含匹配，则返回 null。否则，结果列表中的每个项目是来自 input 的匹配 pattern 的不同子字符串或 字节序列。end-pos 参数可以是 #f， 以匹配到 input 的末尾（如果 input 是 输入端口，则对应文件结尾）。

Examples:
> (regexp-match* #rx"x." "12x4x6")

'("x4" "x6")

> (regexp-match* #rx"x*" "12x4x6")

'("" "" "x" "" "x" "" "")

match-select 函数指定收集的结果。默认的 car 意味着结果是匹配列表，不返回带括号的子模式。 它可以作为“选择器”函数给出，该函数从列表中选择一个项目， 或者可以选择一个项目列表。例如，你可以使用 cdr 获取带括号的子模式匹配的列表的列表，或使用 values （作为恒等函数）同时获取完整匹配。（注意，选择器必须选择 其输入列表的一个元素或一个元素列表，但不能检查其输入， 因为它们可以是字符串列表或位置对列表。此外，选择器在其 选择中必须一致。）

Examples:
> (regexp-match* #rx"x(.)" "12x4x6" #:match-select cadr)

'("4" "6")

> (regexp-match* #rx"x(.)" "12x4x6" #:match-select values)

'(("x4" "4") ("x6" "6"))

此外，将 gap-select 指定为非 #f 值会使 结果成为一个交错列表，包含匹配以及匹配之间的分隔符， 以分隔符开始和结束。在这种情况下，可以将 match-select 设置为 #f 以仅返回分隔符， 使这种用法等同于 regexp-split。

Examples:
> (regexp-match* #rx"x(.)" "12x4x6" #:match-select cadr #:gap-select? #t)

'("12" "4" "" "6" "")

> (regexp-match* #rx"x(.)" "12x4x6" #:match-select #f #:gap-select? #t)

'("12" "" "")

procedure

(regexp-replace pattern 
  input 
  insert 
  [input-prefix]) 
 → 
(if (and (or (string? pattern) (regexp? pattern))
         (string? input))
    string?
    bytes?)
  pattern : (or/c regexp? byte-regexp? string? bytes?)
  input : (or/c string? bytes?)
  insert : 
(or/c string? bytes?
      (string? string? ... . -> . string?)
      (bytes? bytes? ... . -> . bytes?))
  input-prefix : bytes? = #""
使用 pattern 对 input 执行匹配，然后 返回一个字符串或字节字符串，其中 input 的匹配部分 被替换为 insert。如果 pattern 不匹配 input 的任何部分，则原样返回 input。

insert 参数可以是（字节）字符串，也可以是返回 （字节）字符串的函数。在后一种情况下，函数应用于 regexp-match 将返回的值列表（即第一个参数是 完整匹配，然后每个带括号的子表达式一个参数）以获取替换的 （字节）字符串。

如果 pattern 是字符串或字符 regexp 且 input 是字符串，则 insert 必须是字符串或接受字符串的过程，且结果为字符串。如果 pattern 是字节字符串或字节 regexp，或者 input 是字节字符串，则 insert 作为字符串时被转换为字节字符串，insert 作为过程时以字节字符串为参数调用，且结果为字节字符串。

如果 insert 包含 &，则在代入匹配位置 之前，& 被替换为 input 的匹配部分。 如果 insert 包含某个整数 ‹n› 的 \‹n›，则它被替换为 input 中的 第 ‹n› 个匹配子表达式。& 和 \0 是别名。如果第 ‹n› 个子表达式未 在匹配中使用，或者 ‹n› 大于 pattern 中子表达式的数量，则 \‹n› 被替换为 空字符串。

要替换字面的 & 或 \，分别在 insert 中使用 \& 和 \\。insert 中的 \$ 等同于空序列；这可以用来终止 \ 后面的数字 ‹n›。如果 insert 中的 \ 后跟数字、&、\ 或 $ 以外的任何内容，则 \ 本身被视为 \0。

请注意，前面段落中描述的 \ 是 insert 的字符或字节。要将这样的 insert 写成 Racket 字符串字面量，需要在 \ 之前使用转义 \。例如，Racket 常量 "\\1" 是 \1。

Examples:
> (regexp-replace #rx"mi" "mi casa" "su")

"su casa"

> (regexp-replace #rx"mi" "mi casa" string-upcase)

"MI casa"

> (regexp-replace #rx"([Mm])i ([a-zA-Z]*)" "Mi Casa" "\\1y \\2")

"My Casa"

> (regexp-replace #rx"([Mm])i ([a-zA-Z]*)" "mi cerveza Mi Mi Mi"
                  "\\1y \\2")

"my cerveza Mi Mi Mi"

> (regexp-replace #rx"x" "12x4x6" "\\\\")

"12\\4x6"

> (display (regexp-replace #rx"x" "12x4x6" "\\\\"))

12\4x6
