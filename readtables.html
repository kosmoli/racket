读取器扩展🔗

Racket 的读取器可以通过三种方式扩展：通过 readtable 中的 reader-macro 过程（参见 读取表）、通过 #reader 形式（参见 (part "parse-reader")）， 或通过返回"special"结果过程的 custom-port byte reader（参见 (part "customport")）。 所有这三种 reader extension procedures 接受类似的参数，并且它们的结果 由 read 和 read-syntax（或更准确地说，由默认的 read handler； 参见 port-read-handler）以相同方式处理。

1 读取表🔗

(part "default-readtable-dispatch") 中的调度表对应于默认的 readtable。 通过创建新的 readtable 并通过 current-readtable 参数安装它，可以扩展读取器的行为。

读取器在特定时间查阅 readtable：

  • 查找 datum 的起始位置时；

  • 确定如何解析以 # 开头的 datum 时；

  • 查找分隔符以终止 symbol 或 number 时；

  • 在解析为 pair、list、vector 或 hash table 的序列的第一个字符之后， 查找 opener（如 (）、closer（如 )）或 . 时；或

  • 在指定长度 ‹n› 的 vector 中，#‹n› 之后查找 opener 时。

在其他时候，readtable 会被忽略。特别是，在解析了一个被映射到 ; 的默认行为的字符之后，readtable 直到发现注释的终止换行符时才被忽略。类似地，直到找到闭合双引号之前， readtable 不影响 string 解析。同时，如果一个字符被映射到 ( 的默认行为， 那么它启动一个序列，该序列由任何映射到闭合括号 ) 的字符关闭。 一个明显的例外是，| 的默认解析引用一个 symbol 直到找到匹配字符， 但解析器只是使用启动引用的字符；它不查阅 readtable。

对于许多上下文，#f 标识默认的 readtable。特别是，#f 是 current-readtable 参数的初始值，使读取器表现为 (part "reader") 中描述的行为。

procedure

(readtable? v) → boolean?

  v : any/c
如果 v 是 readtable，则返回 #t，否则返回 #f。

procedure

(make-readtable readtable key mode action ...) → readtable?

  readtable : (or/c readtable? #f)
  key : (or/c char? #f)
  mode : 
(or/c 'terminating-macro
      'non-terminating-macro
      'dispatch-macro
      char?)
  action : 
(or/c procedure?
      readtable?
      #f)
创建一个类似于 readtable（可以是 #f 表示默认 readtable）的新 readtable， 但读取器对每个 key 的行为根据给定的 mode 和 action 进行修改。 make-readtable 的 ... 适用于 key、mode 和 action 全部三个； 换句话说，make-readtable 的参数总数必须为 1 对 3 取模。

key、mode 和 action 的可能组合如下：

  • char 'terminating-macro proc — 使 char 被解析为分隔符，并且输入字符串中未引用/未注释的 char 触发对 reader macro proc 的调用；proc 的活动将在下面进一步描述。 从概念上讲，像 ;、( 和 ) 这样的字符在默认 readtable 中 被映射到 terminating reader macro。

  • char 'non-terminating-macro proc — 类似于 'terminating-macro 变体，但 char 不被视为分隔符， 因此它可以在 identifier 或 number 的中间使用。从概念上讲，# 在默认 readtable 中 被映射到 non-terminating macro。

  • char 'dispatch-macro proc — 类似于 'non-terminating-macro 变体，但仅当 char 跟随在 # 之后时 （或者更准确地说，当字符跟随在已映射到默认 readtable 中 # 行为的字符之后时）。

  • char like-char readtable — 使 char 的解析方式与 like-char 在 readtable 中的解析方式相同， 其中 readtable 可以是 #f 表示默认 readtable。（char 的映射 不适用于 # 之后，# 通过 'dispatch-macro 单独配置。） 将字符映射到与默认读取器中 | 相同的操作意味着该字符开始引用 symbol， 并且相同的字符终止引用；相反，将字符映射到与 " 相同的操作意味着 该字符开始一个 string，但 string 仍然以闭合的 " 终止。最后， 将字符映射到默认 readtable 中的操作意味着该字符的行为对影响原始字符的参数敏感； 例如，将字符映射到与默认 readtable 中花括号 { 相同的操作意味着 当 read-curly-brace-as-paren 参数设置为 #f 时，该字符被禁止。

  • #f 'non-terminating-macro proc — 替换用于解析没有特定映射的字符的 macro：即，可以使用默认 readtable 启动 symbol 或 number 的字符 （# 或 | 除外）。

如果为单个 char 提供了多个 'dispatch-macro 映射，除最后一个外其余都被忽略。 类似地，如果为单个 char 提供了多个非 'dispatch-macro 映射， 除最后一个外其余都被忽略。

Reader macro proc 必须接受六个参数，并且可以可选地接受两个参数。 前两个参数始终是触发 reader macro 的字符和用于读取的输入端口。 当 reader macro 由 read-syntax（或 read-syntax/recursive）触发时， 过程会收到四个额外参数，表示已消耗字符的源位置：source name、line number 或 #f、 column number 或 #f 以及 position 或 #f。当 reader macro 由 read （或 read/recursive）触发时，如果过程接受两个参数，则只传递两个参数， 否则传递六个参数，其中第三个始终是 #f。有关过程结果的信息，请参见 Reader 扩展过程。

Reader macro 通常从给定的输入端口读取字符，以产生用作消耗字符的 "reader-macroid-expansion" 的值。 Reader macro 可能产生 special-comment 值（参见 特殊注释），使消耗的字符被视为 whitespace， 并且可能使用 read/recursive 或 read-syntax/recursive。

procedure

(readtable-mapping readtable char)

 → 
(or/c char?
      'terminating-macro
      'non-terminating-macro)
(or/c #f procedure?)
(or/c #f procedure?)
  readtable : readtable?
  char : char?
产生关于 readtable 中 char 的映射信息。结果是三个值：

  • 要么是一个字符（映射到与默认 readtable 中该字符相同的行为），要么是 'terminating-macro，要么是 'non-terminating-macro；此结果报告 char 的主要（即非 'dispatch-macro）映射。当结果是一个字符时，char 被映射到与默认 readtable 中返回字符相同的行为。

  • 要么是 #f，要么是一个 reader-macro 过程；当第一个结果是 'terminating-macro 或 'non-terminating-macro 时，结果是一个过程。

  • 要么是 #f，要么是一个 reader-macro 过程；当该字符在 readtable 中有 'dispatch-macro 映射以覆盖默认 dispatch 行为时，结果是一个过程。

请注意，默认 readtable 的 reader-macro 过程不能直接访问。要调用默认行为，请使用 read/recursive 或 read-syntax/recursive，并传入一个字符和 #f readtable。

Examples:
; Provides raise-read-error and raise-read-eof-error
> (require syntax/readerr)
> (define (skip-whitespace port)
    ; Skips whitespace characters, sensitive to the current
    ; readtable's definition of whitespace
    (let ([ch (peek-char port)])
      (unless (eof-object? ch)
        ; Consult current readtable:
        (let-values ([(like-ch/sym proc dispatch-proc)
                      (readtable-mapping (current-readtable) ch)])
          ; If like-ch/sym is whitespace, then ch is whitespace
          (when (and (char? like-ch/sym)
                     (char-whitespace? like-ch/sym))
            (read-char port)
            (skip-whitespace port))))))
> (define (skip-comments read-one port src)
    ; Recursive read, but skip comments and detect EOF
    (let loop ()
      (let ([v (read-one)])
        (cond
         [(special-comment? v) (loop)]
         [(eof-object? v)
          (let-values ([(l c p) (port-next-location port)])
            (raise-read-eof-error
             "unexpected EOF in tuple" src l c p 1))]
         [else v]))))
> (define (parse port read-one src)
    ; First, check for empty tuple
    (skip-whitespace port)
    (if (eq? #\> (peek-char port))
        null
        (let ([elem (read-one)])
          (if (special-comment? elem)
              ; Found a comment, so look for > again
              (parse port read-one src)
              ; Non-empty tuple:
              (cons elem
                    (parse-nonempty port read-one src))))))
> (define (parse-nonempty port read-one src)
    ; Need a comma or closer
    (skip-whitespace port)
    (case (peek-char port)
      [(#\>) (read-char port)
       ; Done
       null]
      [(#\,) (read-char port)
       ; Read next element and recur
       (cons (skip-comments read-one port src)
             (parse-nonempty port read-one src))]
      [else
       ; Either a comment or an error; grab location (in case
       ; of error) and read recursively to detect comments
       (let-values ([(l c p) (port-next-location port)]
                    [(v) (read-one)])
         (cond
          [(special-comment? v)
           ; It was a comment, so try again
           (parse-nonempty port read-one src)]
          [else
           ; Wasn't a comment, comma, or closer; error
           ((if (eof-object? v)
                raise-read-eof-error
                raise-read-error)
            "expected `,` or `>`" src l c p 1)]))]))
> (define (make-delims-table)
    ; Table to use for recursive reads to disallow delimiters
    ;  (except those in sub-expressions)
    (letrec ([misplaced-delimiter
              (case-lambda
               [(ch port) (misplaced-delimiter ch port #f #f #f #f)]
               [(ch port src line col pos)
                (raise-read-error
                 (format "misplaced `~a` in tuple" ch)
                 src line col pos 1)])])
      (make-readtable (current-readtable)
                      #\, 'terminating-macro misplaced-delimiter
                      #\> 'terminating-macro misplaced-delimiter)))
> (define (wrap l)
    `(make-tuple (list ,@l)))
> (define parse-open-tuple
    (case-lambda
     [(ch port)
      ; ‘read‘ mode
      (wrap (parse port
                   (lambda ()
                     (read/recursive port #f
                                     (make-delims-table)))
                   (object-name port)))]
     [(ch port src line col pos)
      ; ‘read-syntax‘ mode
      (datum->syntax
       #f
       (wrap (parse port
                    (lambda ()
                      (read-syntax/recursive src port #f
                                             (make-delims-table)))
                    src))
       (let-values ([(l c p) (port-next-location port)])
         (list src line col pos (and pos (- p pos)))))]))
> (define tuple-readtable
    (make-readtable #f #\< 'terminating-macro parse-open-tuple))
> (parameterize ([current-readtable tuple-readtable])
    (read (open-input-string "<1 , 2 , \"a\">")))

'(make-tuple (list 1 2 "a"))

> (parameterize ([current-readtable tuple-readtable])
    (read (open-input-string
           "< #||# 1 #||# , #||# 2 #||# , #||# \"a\" #||# >")))

'(make-tuple (list 1 2 "a"))

> (define tuple-readtable+
    (make-readtable tuple-readtable
                    #\* 'terminating-macro (lambda a
                                             (make-special-comment #f))
                    #\_ #\space #f))
> (parameterize ([current-readtable tuple-readtable+])
    (read (open-input-string "< * 1 __,__  2 __,__ * \"a\" * >")))

'(make-tuple (list 1 2 "a"))

2 Reader 扩展过程🔗

对 reader extension procedures 的调用可以通过 read、read/recursive 或 read-syntax 触发。此外，special-read 过程可以通过调用 read-char-or-special 触发，或者通过 read-bytes-avail!、peek-bytes-avail!*、read-bytes-avail! 和 peek-bytes-avail!* 的上下文触发。

reader-macro 和 special-result 过程的可选参数数量允许它们区分通过 read 等进行的读取，与通过 read-syntax 等进行的读取（其中 source 值为 #f 且没有其他位置信息可用）。

当 reader-extension 过程在语法读取模式中（通过 read-syntax 等）被调用时，它通常应返回一个没有词法上下文的语法对象（例如，使用 datum->syntax 创建，以 #f 作为第一个参数，以给定的位置信息作为第三个参数）。另一种可能的结果是 special-comment 值（参见 特殊注释）。如果过程的结果既不是语法对象也不是 special-comment 值，则使用 datum->syntax 将其转换为语法对象。

当 reader-extension 过程在非语法读取模式中被调用时，它通常不应返回语法对象。如果返回语法对象，则使用 syntax->datum 将其转换为普通值。

在任何一种上下文中，当 reader-extension 过程的结果是 special-comment 值（参见 特殊注释）时，read、read-syntax 等过程将该值视为分隔注释并忽略它。

此外，在任何一种上下文中，结果可能被复制以防止在读取结果完成之前对向量或 box 的修改，并支持构建带环的图。可变的 box、向量和 prefab 结构会被复制，包括任何导致此类可变值的 pair、box、向量、prefab 结构，递归读取产生的占位符（参见 read/recursive），或者共享值的引用。图结构（包括环）在复制中得以保留。

3 特殊注释🔗

procedure

(make-special-comment v) → special-comment?

  v : any/c
创建一个封装 v 的 special-comment 值。read、read-syntax 等过程会将由 make-special-comment 构造的值在由 reader-extension 过程返回时视为分隔空白（参见 Reader 扩展过程）。

procedure

(special-comment? v) → boolean?

  v : any/c
如果 v 是 make-special-comment 的结果，则返回 #t，否则返回 #f。

procedure

(special-comment-value sc) → any

  sc : special-comment?
返回由 special-comment 值 sc 封装的值。该值永远不会被读取器直接使用，但可能被检测到特殊注释的 read-char-or-special 等调用的上下文使用。
