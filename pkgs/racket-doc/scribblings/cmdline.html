 (require racket/cmdline) package: base
The bindings documented in this section are provided by the racket/cmdline and racket libraries, but not racket/base.

syntax

(command-line optional-name-expr optional-argv-expr
              flag-clause ...
              finish-clause)
 
optional-name-expr = 
  | #:program name-expr
     
optional-argv-expr = 
  | #:argv argv-expr
     
flag-clause = #:multi flag-spec ...
  | #:once-each flag-spec ...
  | #:once-any flag-spec ...
  | #:final flag-spec ...
  | #:usage-help string ...
  | #:help-labels string ...
  | #:ps string ...
     
flag-spec = (flags id ... help-spec body ...)
  | (flags => handler-expr help-expr)
     
flags = flag-string
  | (flag-string ...+)
     
help-spec = string
  | (string-expr ...+)
     
finish-clause = 
  | #:args arg-formals body ...
  | #:handlers handlers-exprs
     
arg-formals = rest-id
  | (arg ...)
  | (arg ...+ . rest-id)
     
arg = id
  | [id default-expr]
     
handlers-exprs = finish-expr arg-strings-expr
  | finish-expr arg-strings-expr help-expr
  | 
finish-expr arg-strings-expr help-expr
unknown-expr
根据 flag-clause 中的规范解析命令行。

如果提供了 name-expr，它应生成一个路径或字符串，用于在命令行格式错误时作为程序名称报告错误。它默认为 (find-system-path 'run-file)。当提供路径时，仅使用路径的最后一个元素来报告错误。

如果提供了 argv-expr，它必须评估为字符串列表或向量。它默认为 (current-command-line-arguments)。

命令行被拆解为标志（每个标志可能有标志特定参数）后跟（非标志）参数。以 - 或 + 开头的命令行字符串被解析为标志，但标志的参数永远不会被解析为标志，以 - 或 + 开头的整数和十进制数字不被视为标志。命令行中的非标志参数必须出现在所有标志及其参数之后。第一个非标志参数之后的任何命令行字符串都不会被解析为标志。内置的 -- 标志表示命令行标志的结束；-- 标志之后的任何命令行字符串都被解析为非标志参数。

#:multi、#:once-each、#:once-any 或 #:final 子句引入一组命令行标志规范。子句标签指示标志可以在命令行上出现的次数：

  • #:multi — 集合中指定的每个标志可以在命令行上出现任意次数；即集合中的标志是独立的，每个标志可以使用多次。

  • #:once-each — 集合中指定的每个标志可以在命令行上出现一次；即集合中的标志是独立的，但每个标志最多应指定一次。如果标志规范在命令行中出现多次，则 exn:fail exception is raised。

  • #:once-any — 集合中指定的只有一个标志可以在命令行上出现；即集合中的标志是互斥的。如果集合在命令行中出现多次，则 exn:fail exception is raised。

  • #:final — 类似于 #:multi，但标志之后的任何参数都不被视为标志。注意，如果 #:final 标志有短名称，则可以指定多个；例如，如果 -a 是 #:final 标志，则 -aa 在单个命令行参数中组合了两个 -a 实例。

正常的标志规范有四个部分：

  • flags — 标志字符串或标志字符串集合。如果提供了一组标志，则所有标志都是等效的。每个标志字符串必须为 "-x" 或 "+x" 形式，其中字符为 x，或为 "--x" 或 "++x" 形式，其中字符序列为 x。x 不能仅包含数字或数字加单个小数点，因为简单（有符号）数字不被视为标志。此外，标志 "--"、"-h" 和 "--help" 是预定义的，不能更改。

  • ids — 绑定到标志参数的标识符。标识符的数量确定可以在命令行上为该标志提供的参数数量，这些标识符的名称将出现在描述标志的帮助消息中。ids 在用于处理标志的 bodys 中绑定到字符串值。

  • help-spec — 描述标志的字符串或字符串序列。此字符串由内置 -h（或 --help）标志的处理程序生成的帮助消息中使用。可以提供单个字面字符串，或任意数量的生成字符串的表达式；在后一种情况下，第一个字符串之后的字符串显示在后续行上。

  • bodys — 当 flags 之一出现在命令行上时评估的表达式。标志从左到右解析，每个 bodys 序列在遇到相应标志时评估。当评估 bodys 时，前面的 ids 绑定到命令行上为该标志提供的参数。

使用 => 的标志规范转义到更通用的指定处理程序和帮助字符串的方法。在这种情况下，handler-expr 和 help-expr 返回的处理程序过程和帮助字符串列表用作 parse-command-line 的 table 参数。

#:usage-help 子句在用例行之后立即插入文本行。子句中的每个字符串提供单独一行文本。

#:help-labels 子句将文本行插入命令行标志的帮助表中。子句中的每个字符串提供单独一行文本。

#:ps 子句在帮助输出末尾插入文本行。子句中的每个字符串提供单独一行文本。

在标志子句之后，最终子句处理未解析为标志的命令行参数：

  • 不提供最终子句等同于提供 #:args () (void)。

  • 对于 #:args 最终子句，arg-formals 中的标识符绑定到剩余的命令行字符串，方式与 lambda 表达式中标识符的绑定方式相同。因此，指定单个 id（不带括号）将所有剩余参数收集到列表中。arg-formals 规范的有效 arity 确定用户可以提供的额外命令行参数数量，arg-formals 中标识符的名称用于帮助字符串。当解析命令行时，如果提供的参数数量无法匹配 arg-formals 中的标识符，则 exn:fail exception is raised。否则，args 子句的 bodys 被评估以处理剩余参数，最后一个 body 的结果是 command-line 表达式的结果。

  • #:handlers 最终子句转义到更通用的处理剩余参数的方法。在这种情况下，表达式的值用作 parse-command-line 的最后两到四个参数。

示例：

(define verbose-mode (make-parameter #f))
(define profiling-on (make-parameter #f))
(define optimize-level (make-parameter 0))
(define link-flags (make-parameter null))
 
(define file-to-compile
  (command-line
   #:program "compiler"
   #:once-each
   [("-v" "--verbose") "Compile with verbose messages"
                       (verbose-mode #t)]
   [("-p" "--profile") "Compile with profiling"
                       (profiling-on #t)]
   #:once-any
   [("-o" "--optimize-1") "Compile with optimization level 1"
                          (optimize-level 1)]
   ["--optimize-2"        (; show help on separate lines
                           "Compile with optimization level 2,"
                           "which includes all of level 1")
                          (optimize-level 2)]
   #:multi
   [("-l" "--link-flags") lf ; flag takes one argument
                          "Add a flag <lf> for the linker"
                          (link-flags (cons lf (link-flags)))]
   #:args (filename) ; expect one command-line argument: <filename>
   ; return the argument as a filename to compile
   filename))

procedure

(parse-command-line name    
  argv    
  table    
  finish-proc    
  arg-help-strs    
  [help-proc    
  unknown-proc]) → any
  name : (or/c string? path?)
  argv : (or/c (listof string?) (vectorof string?))
  table : (listof (cons/c symbol? list?))
  finish-proc : (list? any/c ... . -> . any)
  arg-help-strs : (listof string?)
  help-proc : (string? . -> . any) = (lambda (str) ....)
  unknown-proc : (string? . -> . any) = (lambda (str) ...)
使用 table 中的规范解析命令行。有关命令行解析的概述，参见 command-line 形式，它为大多数目的提供了更方便的表示法。

此过程形式的 table 参数编码 command-line 子句中的信息，除了 args 子句。相反，参数由 finish-proc 过程处理，非标志参数的帮助信息在 arg-help-strs 中提供。此外，finish-proc 过程接收解析标志时累积的信息。help-proc 和 unknown-proc 参数允许无法通过 command-line 实现的自定义。

当没有更多标志时，finish-proc 调用时接收为命令行标志累积的信息列表（见下文）和命令行中剩余的非标志参数。finish-proc 的 arity 确定接受和要求的非标志参数数量。例如，如果 finish-proc 接受两或三个参数，则命令行上必须提供一或两个非标志参数。finish-proc 过程可以有任何 arity（参见 procedure-arity），除了 0 或 0 的列表（即过程必须至少接受一个或多个参数）。

arg-help-strs 参数是标识预期（非标志）命令行参数的字符串列表，每个参数一个。如果允许任意数量的参数，arg-help-strs 中的最后一个字符串代表所有这些参数。

help-proc 过程在命令行包含 -h 或 --help 标志时调用帮助字符串。如果遇到未知标志，则 unknown-proc 过程调用，就像标志处理过程一样（如下所述）；它必须至少接受一个参数（未知标志），但也可以接受更多参数。默认 help-proc 显示字符串并退出，默认 unknown-proc 引发 exn:fail 异常。

table 是标志规范集合的列表。每个集合表示为两个项目的对：模式符号和帮助字符串列表或标志规格列表。模式符号是 'once-each、'once-any、'multi、'final、'help-labels、'usage-help 或 'ps 之一，与 command-line 中的相应子句标签含义相同。对于 'help-labels、'usage-help 或 'ps 模式，提供帮助字符串列表。对于其他模式，提供标志规格列表，其中每个规格将多个标志映射到单个处理程序过程。规格是三个项目的列表：

  • 规格定义的标志字符串列表。参见 command-line 了解标志字符串的格式信息。

  • 当在命令行上找到标志时处理标志及其参数的过程。此处理程序过程的 arity 确定标志消耗的参数数量：处理程序过程调用时传入标志字符串加上命令行中接下来的几个参数，以匹配处理程序过程的 arity。处理程序过程必须至少接受一个参数以接收标志。如果处理程序接受任意多个参数，则所有剩余参数传递给处理程序。处理程序过程的 arity 必须是数字或 arity-at-least 值。

    处理程序的返回值添加到最终传递给 finish-proc 的列表中。如果处理程序返回 #<void>，则不向此列表添加任何值。对于处理程序返回的所有非 #<void> 值，列表中值的顺序与命令行上参数的顺序相同。

  • 用于为规格构造帮助信息的非空列表。列表的第一个元素描述标志；它可以是字符串或非空字符串列表，在后一种情况下，每个字符串显示在单独一行上。主列表的其他元素必须是命名标志预期参数的字符串。规格提供的额外帮助字符串数量必须与规格处理程序过程接受的参数数量匹配。

以下示例是与 command-line 的核心示例相同，转换为过程形式：

(parse-command-line "compile" (current-command-line-arguments)
  `((once-each
     [("-v" "--verbose")
      ,(lambda (flag) (verbose-mode #t))
      ("Compile with verbose messages")]
     [("-p" "--profile")
      ,(lambda (flag) (profiling-on #t))
      ("Compile with profiling")])
    (once-any
     [("-o" "--optimize-1")
      ,(lambda (flag) (optimize-level 1))
      ("Compile with optimization level 1")]
     [("--optimize-2")
      ,(lambda (flag) (optimize-level 2))
      (("Compile with optimization level 2,"
        "which implies all optimizations of level 1"))])
    (multi
     [("-l" "--link-flags")
      ,(lambda (flag lf) (link-flags (cons lf (link-flags))))
      ("Add a flag <lf> for the linker" "lf")]))
   (lambda (flag-accum file) file)
   '("filename"))
