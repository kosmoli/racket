库与集合🔗

库是为多个程序提供服务的 module 声明。Racket 进一步将库组合成 集合。集合通常通过 包添加（参见 (part ("(lib pkg/scribblings/pkg.scrbl)" "top"))）；包管理器在 Racket 核心之外运行，但通过 集合链接文件配置核心运行时系统。

集合中的库通过 lib 路径（参见 require）或符号简写引用。例如，以下模块使用 "setup" 集合中的库模块 "getinfo.rkt"，以及 "games" 集合的 "cards" 子集合中的库模块 "cards.rkt"：

#lang racket
(require (lib "setup/getinfo.rkt")
         (lib "games/cards/cards.rkt"))
....

此示例使用符号简写可以更简洁、更常见地书写：

#lang racket
(require setup/getinfo
         games/cards/cards)
....

当在 require 形式中使用标识符 id 时，它会被转换为 (lib rel-string)，其中 rel-string 是 id 的字符串形式。

(lib rel-string) 中的 rel-string 由一个或多个命名集合的路径元素组成，然后是命名库文件的最终路径元素；路径元素之间用 / 分隔。如果 rel-string 不包含任何 /，则隐式地在路径末尾添加 /main.rkt。如果 rel-string 包含 / 但没有以文件后缀结尾，则隐式地在路径末尾添加 .rkt。

库也可以通过 PLaneT 包分发。这类库通过 planet 模块路径引用（参见 require），由 Racket 按需下载，而不是通过 集合引用。

planet 或 lib 路径到 module 声明的转换由 模块名解析器决定，正如 current-module-name-resolver 参数所指定的。

1 集合搜索配置🔗

对于默认的 模块名解析器，集合的搜索路径由 current-library-collection-links 参数和 current-library-collection-paths 参数决定：

  • 最原始的基于 集合的模块位于相对于 Racket 可执行文件的 "collects" 目录中。集合的库分组在名称与集合名称匹配的目录内。"collects" 目录的路径通常包含在 current-library-collection-paths 中。

  • 基于集合的库也可以安装在其他目录中，可能是用户特定的目录，其结构与 "collects" 目录相同。这些额外目录可以通过命令行参数传递给 racket 动态地包含在 current-library-collection-paths 参数中，或通过设置 PLTCOLLECTS 环境变量；参见 find-library-collection-paths。

  • 集合链接文件提供从顶级集合名称到目录的映射，加上额外的 "collects" 类目录（这些子目录名称与集合名称匹配）。要搜索的每个 集合链接文件由 current-library-collection-links 参数引用；该参数引用文件本身而非文件内容，以便文件的更改可以被检测并影响后续的模块解析。另请参见 find-library-collection-links。

  • current-library-collection-links 参数的值还可以包含哈希表，这些哈希表提供与 集合链接文件相同的内容：从符号形式的集合名称到集合路径列表的映射，或从 #f 到 "collects" 类路径列表的映射。

  • 最后，current-library-collection-links 参数的值包含 #f 来表示搜索过程中的一个检查点，在该点 模块名解析器 应该检查 current-library-collection-paths 相对于 current-library-collection-links 中的文件和哈希表。

为了解析模块引用 rel-string，默认的 模块名解析器 按从先到后的顺序搜索 current-library-collection-links 中的集合链接，以定位包含 rel-string 的第一个目录，在 current-library-collection-links 包含 #f 的位置拼接对 current-library-collection-paths 的搜索。链接表和搜索路径中每个元素的文件系统树实际上与对应同一集合的其他路径元素的文件系统树 拼接在一起。一些 Racket 工具依赖于模块路径名的唯一解析，因此安装和配置不应允许多个文件匹配同一集合和文件的组合。

current-library-collection-links 参数的值由 racket 可执行文件初始化为 (find-library-collection-links) 的结果，current-library-collection-paths 参数的值初始化为 (find-library-collection-paths) 的结果。

2 集合链接🔗

集合链接文件被 collection-file-path、collection-path 和默认的 模块名解析器 用来在尝试 (current-library-collection-paths) 搜索路径之前定位集合。要使用的 集合链接文件由 current-library-collection-links 参数决定，该参数被初始化为 find-library-collection-links 的结果。

集合链接文件使用默认的读取器参数设置被 read 以获得一个列表。列表的每个元素必须是一个具有以下形式之一的链接规范：(list string encoded-path)、(list string encoded-path regexp)、(list 'root encoded-path)、(list 'root encoded-path regexp)、(list 'static-root encoded-path)、(list 'static-root encoded-path regexp)。

string 命名一个顶级 集合，在此情况下 encoded-path 描述一个可以用作集合路径的路径（直接作为路径，而非由 string 命名的 encoded-path 的子目录）。相比之下，'root 条目就像 (current-library-collection-paths) 中的路径一样运作。'static-root 条目类似于 'root 条目，但假设目录的即时内容不会改变，除非 集合链接文件发生变化。

每个 encoded-path 要么是一个字符串，要么是一个通过 bytes->path 转换为路径的字节字符串，要么是一个由相对路径元素字节字符串、'up 和 'same 指示符组成的列表，这些与 build-path 组合，其中字节字符串通过 bytes->path-element 转换。

如果 encoded-path 描述的是相对路径，则它相对于包含 集合链接文件 的目录。如果链接中指定了 regexp，则该链接仅在 (regexp-match? regexp (version)) 产生真值结果时被使用。

单个顶级集合在 集合链接文件 中可以有多个链接，并且可以出现任意数量的 'root 条目。对应的路径有效地被拼接在一起，因为路径是按顺序尝试以定位文件或子集合的。

raco link 命令行工具可以显示、安装和删除 集合链接文件 中的链接。更多信息参见 (part ("(lib scribblings/raco/raco.scrbl)" "top")) 中的 (part ("(lib scribblings/raco/raco.scrbl)" "link"))。

Changed in version 8.1.0.6: 允许 encoded-path 使用字节字符串和列表。

3 集合路径与参数🔗

procedure

(find-library-collection-paths [pre-extras    
  post-extras    
  config]    
  name) → (listof path?)
  pre-extras : (listof path-string?) = null
  post-extras : (listof path-string?) = null
  config : hash? = (read-installation-configuration-table)
  name : (get-installation-name config)
生成一个路径列表，通常用于初始化 current-library-collection-paths，如下所示：

  • (build-path (find-system-path 'addon-dir) name "collects") 生成的路径是默认集合路径列表的第一个元素，除非 use-user-specific-search-paths 参数的值为 #f。

  • 在 pre-extras 中提供的额外目录接下来被包含在默认集合路径列表中，转换为相对于可执行文件的完整路径。

  • 如果 (find-system-path 'collects-dir) 指定的目录是绝对路径，或者它是相对的（相对于可执行文件）且存在，则它被添加到默认集合路径列表的末尾。

  • 在 post-extras 中提供的额外目录最后被包含在默认集合路径列表中，转换为相对于可执行文件的完整路径。

  • 如果 config 有 'collects-search-dirs 的值，则它用来代替默认集合路径列表（由前三个要点构建），并且默认值被拼接在 'collects-search-dirs 列表中的任何 #f 位置。如果 config 没有 'collects-search-dirs 值，则使用默认集合路径列表。

  • 如果定义了 PLTCOLLECTS 环境变量，则使用 path-list-string->path-list 将其与默认列表组合，只要 use-user-specific-search-paths 的值为真。如果未定义或 use-user-specific-search-paths 的值为 #f，则直接使用由前四个要点构建的集合路径列表。

    注意在 Unix and Mac OS 上，路径用 : 分隔，在 Windows 上用 ; 分隔。此外，path-list-string->path-list 在空路径处拼接默认路径，例如，在许多 Unix shell 中，可以将 PLTCOLLECTS 设置为 ":‘pwd‘"、"‘pwd‘":" 或 "‘pwd‘" 来分别指定在默认路径之后、之前或替代默认当前目录。

Changed in version 8.4.0.3: 添加了 config 和 name 参数。

procedure

(find-library-collection-links [config] name)

 → (listof (or/c #f (and/c path? complete-path?)))
  config : hash? = (read-installation-configuration-table)
  name : (get-installation-name config)
生成一个路径和 #f 的列表，通常用于初始化 current-library-collection-links，如下所示：

  • 列表以 #f 开头，使得默认的 模块名解析器、collection-file-path 和 collection-path 在 集合链接文件之前尝试 current-library-collection-paths 中的路径。

  • 只要 use-user-specific-search-paths 和 use-collection-link-paths 的值为真，结果列表中的第二个元素就是用户特定的 集合链接文件 路径，默认为 (build-path (find-system-path 'addon-dir) name "links.rktd")，但可以被 config 中的 'links-file 值替换。

  • 只要 use-collection-link-paths 的值为真，列表的其余部分包含类似于 get-links-search-files 的结果，但如果提供 config 则使用它而不是读取安装的 "config.rktd" 文件。通常，该结果是包含单个路径 (build-path (find-config-dir) "links.rktd") 的列表。

Changed in version 8.4.0.3: 添加了 config 和 name 参数。

procedure

(collection-file-path file 
  collection ...+ 
  [#:check-compiled? check-compiled?]) 
 → path?
  file : path-string?
  collection : path-string?
  check-compiled? : any/c = (regexp-match? #rx"[.]rkt$" file)
(collection-file-path file    
  collection ...+    
  #:fail fail-proc    
  [#:check-compiled? check-compiled?]) → any
  file : path-string?
  collection : path-string?
  fail-proc : (string? . -> . any)
  check-compiled? : any/c = (regexp-match? #rx"[.]rkt$" file)
返回由 collections 指定的集合中 file 指示的文件的路径，其中第二个 collection（如果有的话）命名一个子集合，依此类推。搜索使用 current-library-collection-links 和 current-library-collection-paths 的值。

另请参见 setup/collection-search 中的 collection-search。

如果未找到 file，但 file 以 ".rkt" 结尾且存在后缀为 ".ss" 的文件，则使用 ".ss" 文件的目录。如果未找到 file 且 ".rkt"/".ss" 转换不适用，但找到了对应于 collections 的目录，则使用第一个这样的目录返回路径。

如果 check-compiled? 为真，则搜索还取决于 use-compiled-file-paths 和 current-compiled-file-roots；如果未找到 file，则按默认 编译加载处理器 的方式检查后缀为 ".zo" 的 file 的编译形式。如果找到编译文件，collection-file-path 的结果报告找到的编译文件对应的 file 本身应占据的位置（如果存在的话）。

最后，如果未找到集合，并且提供了 fail-proc，则将 fail-proc 应用于错误消息（不以 "collection-file-path:" 开头或声称来源），并且其结果作为 collection-file-path 的结果。如果未提供 fail-proc 且未找到集合，则 exn:fail:filesystem exception is raised。

Examples:
> (collection-file-path "main.rkt" "racket" "base")

#<path:path/to/collects/racket/base/main.rkt>

> (collection-file-path "sandwich.rkt" "bologna")

collection-file-path: collection not found

  collection: "bologna"

  in collection directories:

   /opt/racket/collects/

   ... [174 additional linked and package directories]

parameter

(use-user-specific-search-paths) → boolean?

(use-user-specific-search-paths on?) → void?
  on? : any/c
一个参数，用于确定是否将用户特定路径包含进搜索路径中，这些路径位于 (find-system-path 'addon-dir) 生成的目录中，用于搜索集合和其他文件。例如，当此参数的值为 #f 时，find-library-collection-paths 的初始值会省略用户特定的集合目录。

如果 racket 有 -U 或 --no-user-path 参数，则 use-user-specific-search-paths 被初始化为 #f。

parameter

(use-collection-link-paths) → boolean?

(use-collection-link-paths on?) → void?
  on? : any/c
一个参数，用于确定 集合链接文件是否包含在 find-library-collection-links 的结果中。

如果此参数在启动时的值为 #f，则 集合链接文件对该 Racket 进程永久禁用。特别是，如果将空字符串作为 -X 或 --collects 参数提供给 racket，则不仅 current-library-collection-paths 被初始化为空列表，而且 use-collection-link-paths 也被初始化为 #f。

procedure

(read-installation-configuration-table)

 → (and/c hash? immutable?)
返回安装的 "config.rktd" 文件的内容（参见 (part ("(lib scribblings/raco/raco.scrbl)" "config-file"))），只要该内容是 哈希表，否则返回空哈希表。
