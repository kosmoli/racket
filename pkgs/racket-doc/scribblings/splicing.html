splicing-parameterize

与 let（不是 named let）、letrec、let-values、letrec-values、let-syntax、letrec-syntax、let-syntaxes、letrec-syntaxes、letrec-syntaxes+values、local 和 parameterize 类似，不同之处在于，在定义上下文中，body 形式被拼接到封闭的定义上下文中（与 begin 相同）。

Examples:
> (splicing-let-syntax ([one (lambda (stx) #'1)])
    (define o one))
> o

1

> one

one: undefined;

 cannot reference an identifier before its definition

  in module: top-level

当拼接绑定形式出现在 top-level context 或 module context 中时，其局部绑定被视为类似定义。特别是，语法绑定在每次 visit 模块时求值，而不是像 let-syntax 等仅在编译期间求值一次。

Example:
> (splicing-letrec ([x bad]
                    [bad 1])
    x)

bad.1: undefined;

 cannot reference an identifier before its definition

  in module: top-level

如果拼接形式中的定义旨在成为拼接 body 的局部，则标识符应具有 'definition-intended-as-local syntax property 的真值。例如，splicing-let 本身在展开为定义序列时会将属性添加到局部绑定的标识符中，以便将 splicing-let 嵌套在拼接形式中按预期工作（没有任何歧义的绑定）。

Changed in version 6.12.0.2 of package base: 添加 splicing-parameterize。

splicing-syntax-parameterize

与 syntax-parameterize 类似，不同之处在于，在定义上下文中，body 形式被拼接到封闭的定义上下文中（与 begin 相同）。在定义上下文中，splicing-syntax-parameterize 的 body 可以为空。

注意 require transformers 和 provide transformers 不受语法参数化的影响。虽然所有 require 和 provide 的使用将被拼接到封闭的上下文中，但派生的导入或导出规范将展开，就像它们不在 splicing-syntax-parameterize 内一样。

此外，使用 module* 定义的 submodules 在 module path 位置指定 #f 时会受语法参数化的影响，但其他 submodule（那些使用 module 或具有 module path 的 module* 定义的）不受影响。

Examples:
> (define-syntax-parameter place (lambda (stx) #'"Kansas"))
> (define-syntax-rule (where) `(at ,(place)))
> (where)

'(at "Kansas")

> (splicing-syntax-parameterize ([place (lambda (stx) #'"Oz")])
    (define here (where)))
> here

'(at "Oz")

Changed in version 6.11.0.1 of package base: 修改为语法参数化 module* submodule，这些 submodule 在 module path 位置指定 #f。
